# Game data and logic (`apps/web/src/games/alttpr/data/`, `apps/web/src/games/alttpr/logic/`)

ALttPR's modules live under `apps/web/src/games/alttpr/`: a short path below (`logic/…`, `stores/gameStore.ts`, `map/…`, `autotrack/follow.ts`) is relative to it, unless it names one of the shared modules (`components/ui/` Modal, Tabs, ConfirmDialog, ToolbarMenu, ToolbarIcons, UpdatePrompt, Header; `autotrack/guide.ts`, `autotrack/status.ts`; `hooks/` useGridNavigation, useNow, useToolbarFit, useTooltip; `stores/` tooltipStore, updateStore; `utils/`; `styles/`).

The rules are the alltpr pack's (`packs/alttpr`, ALttPR v31): the app holds no predicate of its own. It reads the pack through `apps/web/src/games/alttpr/logic/`:

- `logic/settings.ts` — what the app's run types mean to the pack (`packSettings`, a hidden setting passed as the pack's `UNKNOWN`: the logic of the run's glitches (`LOGICS`; No Logic through the pack's `noLogicSettings`, read with NoGlitches' rules) and randomized weapons in the Open, Standard or Inverted world (`worldOf` names it, the key of what is kept per world), with the run's goal, crystals, swords, item placement, accessibility, item pool and functionality, boss shuffle (`enemizer.bossShuffle`), its dungeon items (`dungeonItems`: standard, mc, mcs or full, which of them may leave their dungeons)), the grid's dungeon indices (`dungeonAt`, `dungeonName`, by the pack's `LEGACY_DUNGEONS`) and where each dungeon counter starts (`counterMax`, from `dungeonItemCount`).
- `logic/packItems.ts` — `PACK_ITEMS`, the one table from each of the tracker's item ids to what its value records for the pack (an item and how it counts, a dungeon beaten, a prize, nothing). `packReading` reads a run through it and `itemsFromPack` turns pack item counts (an autotracker's reading) back into the tracker's values. `RECORDED_LEVELS` lists every pack item the cells can record, at the highest level they reach: what the blockers may propose. `hearts` (kind `hearts`) is Link's hearts on screen and `heartquarters` (kind `quarters`, read by the hearts' entry) the pieces toward the next: `packReading` gives the hearts found beyond the 3 he starts with as heart containers then pieces, then the quarters as pieces (never past the pool's 24), to which the pack's `toState` adds those 3 (`PRE_COLLECTED_STATE`: every world is given them, so a state's hearts are those on screen and `RECORDED_LEVELS` reaches its 14 containers), and while not set (0) the pack's `unknown.health`; the escape's Ten Bombs, which no cell draws, are `tenbombs` (kind `known`: 0 not known, so `unknown.bombs`, 1 none, 2 found), set by autotracking alone (the pack's `src/unknown-counts.ts`: a rule asking for an unknown count is maybe at most). Autotracking alone sets three more kinds no cell draws: `escape` (kind `escape`, values `ESCAPE`: 0 not known, Hyrule Castle counted finished as a run by hand counts it; 1 Zelda not yet in the Sanctuary, so not finished; 2 done; read outside Race Mode only, the game's alone (a merge takes its value), and it never sticks: a race reading lays 0, and Race Mode coming on, the connection lost, autotracking stopped (`forgetEscape` in `stores/autotrackStore.ts`), New game, an import or a shared run (`loadProgress`, `withoutEscape`) set it back to 0; the race relay never carries it), `fluteactive` (kind `activation`, values `ACTIVATION`: 0 not read, the flute as its cell says; 1 Race Mode, which never reads it, so the pack's `unknown.flute`, its fact held only with a flute; 2 read, not activated; 3 read, activated, the flute at 2 while its cell holds it) and `heldgreen`, `heldpendants`, `heldcrystals` (kind `held`: the prizes Link holds by class, whichever dungeon gave them, the crystals counted and never told 5/6; `packReading` hands them to the pack's `TrackerInput.held`, which tops the dungeons' prizes up, regular crystals first). None is a timeline find nor in `RECORDED_LEVELS`. `logic/atoms.spec.ts` holds every atom the rules read, in every world the app compiles, to what the board can satisfy: a new rule over something no cell records fails it until it is recorded, read as unknown, or a reviewed exception. An item added to `data/items.ts` gets its entry here, and every reader picks it up; its spec holds the table to the pack's legacy copy for the version 5 ids.
- `logic/solution.ts` — the run solved: `trackerInput` reads the store's items (through `packReading`), pads and keys as the pack's `TrackerInput`; `solutionOf` runs `toState` and the key model (`solveWithKeys`) in the world compiled once per settings, memoized on the four slices it reads and the events checked (the pack's `EVENT_CHECKS`: the Bomb Merchant, whose big bomb Inverted's Pyramid Fairy wants), with no second store. A `crossedLogic` run takes its tris from the entrance randomizer's world for the entrances noted (the `entrances` slice joins the memo), once `logic/crossed.ts` is loaded (`hooks/useCrossedLogic.ts`, both views; `setCrossedSolver` sets the store again so every selector solves anew), every check maybe until then; its go mode steps through that world, and so does its analysis (`analyzeFacts`, through the lazy solver). The solution keeps each location's tri and what can be seen of it (the engine's visible channel). `trickSolutionOf` solves the same run again in the pack's tricks world with the tricks the player knows held (`{ ...solution.keyed.state, ...trickState(techniques) }` through `solveWithKeys(trickFiller(settings), …)`, so the in-logic key facts, `podFewerKeysSuffice` included, never move); it is synchronous, memoized on the solution and the list of tricks, and undefined when the pref is off or empty, the run is not modelled or is a `crossedLogic` one. `warmTricks` compiles that world ahead, at idle, when the Tricks dialog opens. `marginOf(solution)` solves the same run again in the pack's margin world (`{ ...solution.keyed.state, ...MARGIN_STATE }` through `solveWithKeys(marginFiller(settings), …)`: basic placement's safety margins dropped (the dungeons' health gates, the seven bosses' weapons, Turtle Rock's laser bridge, Ganon's better sword and silvers: the pack's `MARGIN_GATES`), nothing else), memoized per solution in a `WeakMap`, undefined but with basic placement known (`settings.basicPlacement === true`), a modelled logic and no crossed world; `marginSolutionOf(state)` is it while `marginShown` (Basic placement, not hidden, modelled, not `crossedLogic`), which the legend and the Checks filter read without solving. Markers and dungeons read both through `markerStateOf` (`locationStatus`: available > possible > margin > trick > seen > unavailable, seen being out of logic but in sight, margin out of logic but opened without the margin (nothing to learn, only the hearts or gear the seed waits for, so above a trick, which asks a technique), trick out of logic but opened by a trick known; both are solved only for a location that is out of logic, and a dungeon's square and boss are `margin` or `trick` when the pigeonhole rule or the prize's tri says so in that world), `dungeonStateOf` (the pigeonhole rule over a counter), `bossStateOf` and the hooks `useLocationStatus`, `useMarkerStatus`, `useDungeonStatus`, `useBossStatus`, which return strings so a click re-renders only what it changed. `locationStateOf` is one location's: done once checked.
- `logic/checks.ts` — the Checks list's model: `zonesOf` groups the map's locations by zone in upstream's world order (a dungeon's under its name, Hyrule Castle for upstream's Escape; any other under its region's), memoized per world; `checkStates` says what each shows, every check of a dungeon counted out done but its boss location's (`isCountedOut` in `logic/solution.ts`: the counter at 0 while no check of the dungeon but its boss's is ticked; once one is, each check shows its own state, since the counter counts items and a chest left at 0 may hold the dungeon's map, compass or keys unopened; `clearedStateOf`: the boss's own state until beaten; `bossLocationOf` finds it through the pack's `bossLocation`, the dungeon's one location of kind `drop`, none for Hyrule Castle, Castle Tower and Ganon's Tower).
- `logic/missing.ts` — what each check not in logic is missing and the go mode's blockers (`analyzeRun`: the engine's `analyze` and `explain` in the state with every untracked key held, proposing only `RECORDED_LEVELS`; given the run's `TrickSolution`, it asks the pack's tricks world (`trickFiller`, the same state, only the tricks known acquirable at level 1, three atoms at most) what brings each location out of logic that the tricks open, and sets `Missing.tricks` to those sets of `TrickId`s, `RunAnalysis.tricks` keeping the list of tricks it was worked out for; a location out of logic that `marginOf` opens gets `Missing.margin` (`gates`: the fewest margins that open it, the margin world asked with only the margins' items acquirable, as the tricks are; `hearts`, Link's hearts on screen, when one of its `inLogic` ways asks for hearts), its `inLogic` saying what the seed waits for; for a `crossedLogic` run, `analyzeCrossed` over the entrance randomizer's world, its facts read through as the items that bring them), and `goModeStatusOf`, memoized on the solution, beside `goModeMarginOf` (the go mode at `no` but `yes` or `maybe` in the margin world, memoized on the solution too). The go mode's analysis (`RunAnalysis.goMode`, a `GoModeLeft`) is asked with every crystal held (the rules' `crystal` group), since the player counts crystals on the board: its ways in items fewest first; `crystals` when nothing else is left (the ways as the run stands are not empty); `nothing` when in logic with every untracked key (the key model may still say maybe); `unknown` when no three items bring it and everything held (the pack's `everything`) would not either, a setting or a placement it hangs on; `door` in a crossed run (`goModeLeftOf` decides). `analyzeRun` costs milliseconds for the world, so it never runs on a click: `hooks/useRunAnalysis.ts` schedules it at idle into `stores/analysisStore.ts`, and holds an analysis current only for its solution and its tricks (the list by identity, none for none): turning the tricks on, off or changing them works it out again. A doubt says what a `maybe` waits on: a key's spots, a pad, a placement, `hearts` (a rule of hearts alone at maybe: the hearts on screen it asks, `basic` for upstream's hasHealth, the basic placement's gate) or `bombs`; `waysOf` (`logic/needs.ts`) words a set's heart containers and pieces, with those held, as the hearts on screen they make ("7 hearts") and drops the sets that then read alike. Over that analysis, `groupMissing` (pure, nothing solved) groups checks that miss the same thing (the same ways, tricks and kinds of doubt: out of logic first), `compactSpots` folds the checks of one room into the room with a count, and `dungeonMissing` applies both to a dungeon's checks and its boss.
- `logic/timeline.ts` — when each thing held was found: the `Stamp` of a change (`stampOf`, read off the run timer of `apps/web/src/utils/runTimer.ts`), `stampTimeline` (what a change of the run's items and checks adds to or drops from the timeline; the same object when nothing dated changed), and what a save's timeline may hold (`isTimelineKey`, `isStamp`). The store keeps it in `Progress` (`.claude/rules/store.md`).
- `logic/voice.ts` — the voice commands: every phrase (`COMMANDS`, built from the shortcut controls `CONTROLS` with the words players say them by) and what it does, the recognizer's grammar (`GRAMMAR`: each phrase after the wake word `tracker`, then `[unk]`), `commandsOf` (a recognized text's commands, none without the wake word) and `changedValue` (a find, not a click: a toggle held, a level up never round to none, a bit added, a named level never lowered, a dungeon count down never below none). Its words must be in the speech model's dictionary (vosk-model-small-en-us-0.15; `node apps/web/scripts/voice-words.mjs <word>...` checks them against the model fetched by `fetch-voice-model`, whose archive has no words.txt): a name it lacks is spoken as words it has ("samaria", "bom boss", "gannon tower", "tri force"). Adding a control to `CONTROLS` fails its spec until a phrase reaches it.
- `logic/crossed.ts` — the logic of a `crossedLogic` run, loaded on demand: the pack's `erWorld` for the run's settings and `crossedConnections` of the entrances noted (a door not noted leads nowhere), built again only when either changes, solved with `solveFactsState` (a `CrossedRun`: the world, the state with its facts, the solution), its go mode (`goModeStatusBy`) and its analysis (`analyzeFacts`). Anything that reads that world goes through it, so its rules stay out of the main bundle.
- `logic/entrances.ts` — the entrance assistant's model over the pack's entrance tables (`entrances.ts`): the run's shuffled pool (`poolOf`: the pack's `crossedPool` or `fullPool` of the Open or Standard world; none for Simple, Restricted or Insanity or for Inverted, whose tables are not ported, which the Entrances tab says plainly), what an entrance may lead to (`targetsFor`, the pack's `targetsOf`), what noting one notes (`notesFor`: a hole with its cave's door), what the doors autotracking shows Link went through note (`gameNotes`: the pack's `linksOf` within `targetsOf`, of rooms alike the one noted there or else one noted nowhere), where each entrance's marker is drawn (`layoutEntrances`, `layoutOf`: its door's spot, pushed clear of neighbours that would hide it, at most 3.5% of its world away), where the map's markers stand (`placeMarkers`: a marker wholly inside one place, by the pack's `PLACE_OF_LOCATION`, above the first door noted to lead there, nowhere until one is) and their words. Only the assistant's lazy components and autotracking's follower (`autotrack/follow.ts`, in a run whose entrances it knows) import it, on demand, so a run without shuffled entrances never loads the tables.
- `logic/knownBosses.ts` — the bosses the player knows under boss shuffle: each grid dungeon's `knownbossN` cell (0 not known, then the pack's `SHUFFLED_BOSSES` from 1; kind `boss` in `PACK_ITEMS`, which `packReading` hands to `TrackerInput.bosses`; no timeline find), the values a slot may take (`knownBossValues`: the bosses its `canPlaceBoss` takes, Kholdstare left out of a known swordless run but in Ice Palace), how a click steps them (`stepKnownBoss`), whether the cell shows (`knownBossShown`: the run's bosses may move, never a swordless Ice Palace) and their words. Ganon's Tower's three slots have no cell.
- `logic/needs.ts` — the engine's blockers in the tracker's words: each atom as the name and icon the player knows (`waysOf`, `sameWays`).

`apps/web/src/games/alttpr/data/`:

- `items.ts` — `ItemState`, `itemGridFor` (the grid of a run, one cached array per kind of run: a retro run adds a row under the grid with the shops, `shoparrow` and `shopkey`, centred, a hunt's pieces between them), `streamGridFor` (the stream view's band: twelve columns, thirteen with Hyrule Castle's key cell, or halves of six on a page taller than wide, the second seven with Hyrule Castle's key cell), and one `[min, max, initial?]` range table from which `items`, `itemsMin` and `itemsMax` are derived, plus `itemLabels` for accessibility names. Do not reintroduce parallel tables. The ids are the tracker's own, which `logic/packItems.ts` maps to the pack's (old saves go through the pack's frozen legacy copy, which `legacy.spec.ts` holds the table to): a dungeon counter's top follows the run's settings (`itemRange` in `stores/persistence.ts`), and `agahnim2` (Ganon's Tower's boss, on its map marker and its grid cell) is the one id version 6 added; `chest12` (Ganon's Tower's items left) came with its cell. `magic` (0 none, 1 half, 2 quarter, as the pack counts it) is a cell that toggles (`TOGGLE_ITEMS`); the logic reads its real value. `hearts` holds the hearts on screen less 2 (`heartsShown`, `heartsValue`: 0 not set, 1 the starting 3, 18 the full 20) and `heartquarters` the pieces toward the next heart (0-3, the game's `HeartPieceQuarter`); they move together as one counter (`Hearts`, read by `heartsOf`, which drops the quarters while not set and at 20): `heartsAfter` steps a quarter (a click, a shortcut; forward from not set is the starting 3, back from them not set, stopping at both ends) or finds a heart (quarters kept) or a piece (voice), and `heartsText` words it ("13 and 2 quarters"). Neither is a timeline find. A Triforce Hunt's pieces are `triforce` (0-50, `PIECES_ITEM`: the pieces found) and `goalpieces` (1-50, 20 at first: the pieces its goal asks for, which no cell draws and autotracking sets from the ROM's `GoalItemRequirement`); `itemGridFor` adds a row with the `triforce` cell under the grid, centred, for a run whose goal is `triforce-hunt` and not hidden (`isHunt`), and both are `PACK_ITEMS` entries of kind `none`, as are what each bottle holds (`bottlecontents1` to `4`, `BOTTLE_SLOTS`: 0 empty then `BOTTLE_CONTENTS`, a bottle being there while its slot is within the `bottle` count, which stays the logic's; `bottleAfter` steps a cell, `withBottleCount` clears the bottles a lower count drops; a save made before them reads its bottles empty) and the bomb and arrow capacities (`bombcapacity`, `arrowcapacity`, flatly, 10 and 30 at the start, `CAPACITIES`, `capacityAfter` 5 a step); none is a timeline find: no rule of the pack reads them, and a hunt's go mode is their count (`goModeStatusOf`, the pack's `huntGoModeOf`: `yes` at the pieces asked for, no step), never solved.
- `keymap.ts` — the keyboard shortcuts, as plain data. The default keys are data (`ITEM_KEYS`), laid as the grid's five-column item block once was, never derived from the grid: no key changes hands when a cell moves, and a control added later (the bottles' contents, the capacities) has no key until the player binds one, so it needs no keymap migration. `ITEM_CONTROLS` leaves out the cells that only show or step a setting (`pendants`, `crystals`, the goal cells) and adds those a cell carries (`arrowcapacity` on the bow's, the bottles' count before the first bottle's). A keymap saved before a cell existed gets its keys in a `migrate` step (`migrateV11`: the half magic's Slash), never moving a chord the player holds.
- `tricks.ts` — the six minor tricks in the player's words (`TRICK_WORDS`: name, one-line summary, https guide links, each video's chapter by its `t=` second; the desktop app opens https only, and the http-only wiki is left out), `MINOR_GLITCHES_GUIDE`, the `tricks` pref's shape (`TrickPrefs`, `DEFAULT_TRICKS`, `restoreTricks`, `withTrick`). Which rules a trick relaxes is the pack's (`packs/alttpr/src/tricks.ts`).
- `presets.ts` — run types (`getPreset`, `presets`, `describeSettings`, which says "?" for a hidden setting). `entrancesKnown(settings)` says whether the assistant knows a run's shuffled entrances (the crossed and full shuffles outside Inverted), without loading the tables. `unmodelledReasons(settings)` lists the causes (a glitched logic behind shuffled entrances, the entrance shuffle, shuffled bosses behind Crossworld entrances), the one place the map's note reads them from, and `logicModelled(settings)` is it empty: whether the pack models a run's rules: vt's NoGlitches without shuffled entrances, the entrance randomizer's for `crossedLogic` runs (the crossed shuffle in the Open or Standard world with `full` dungeon items, Crosskeys', no glitched logic), the glitched logics without shuffled entrances (`Glitches`: alttpr.com's Overworld Glitches, Hybrid Major Glitches, Major Glitches or No Logic, set by a seed's import or autotracking through `checkSeed`, or by hand in the summary's **Glitches** row (`TUNING`, whose None is the value `"none"` there, `glitchesOf`, and the field's absence in a run: `retune` drops it); `GLITCHES_LABELS`); when it does not, `solutionOf` makes every location maybe, the go mode and the analysis say nothing, and the picker marks the run type "logic soon". Mystery starts with every `HIDEABLE` setting hidden: the goal, the swords, the crystals, the item placement, pool and functionality, the accessibility and the boss shuffle, those the pack can leave unknown. `bossShuffle` (`BossShuffle`, alttpr.com's enemizer: none, simple, full, random; absent is none, `bossShuffleOf`; the summary's **Boss shuffle** row) is read by the pack's boss slots (its README, "Boss shuffle"): each dungeon's boss reads as every boss its slot may hold; `bossesMayMove` (set or hidden) keeps a run out of `crossedLogic`, whose entrance randomizer port keeps the vanilla bosses. The world names a run type, and the dungeon items are assumed until set, since the key model and the counters rest on them. A No Logic run (`noLogicRun`) is modelled by what it is played with (`playGlitches`, the summary's **Played with** row shown for it alone, a ported logic's or none, `playGlitchesOf`; `retune` drops it from any other run): `packSettings` reads it with that logic through the pack's `noLogicSettings`, so its map is what those glitches reach, never in logic (the go mode says "reachable", `LogicNote` says why). Every glitched logic is modelled, but behind shuffled entrances (`glitchedLogic`: Overworld Glitches, Hybrid Major Glitches or Major Glitches, which alttpr.com never sends to the entrance randomizer, NoGlitches' alone; `crossedLogic` asks for none). `tunedOf` reads a tunable setting as its options name it. `TUNING` gives each `TunableSetting`'s options (`TuningValue`, a change being a `SettingsChange`), the dungeon items, the glitches and the goal (but Triforce Hunt, a run type of its own) included.
- `apps/web/src/games/alttpr/constants/index.ts` holds only values with game meaning.

## Rules are ported, not remembered

A rule changes in the pack, ported from the randomizer's own source (sporchia/alttp_vt_randomizer at the commit `packs/alttpr/upstream.json` pins) and held to its official tests: see `.claude/rules/pack.md`. The app maps settings and what the player records; it never re-spells a rule.

## Refactor guard

`logic/alttpr.snapshot.spec.ts` freezes what the map shows (every marker, every dungeon's counter and boss) across 15 item states, those the 2017 logic's characterization spec froze. If it moves without an intended rule change, the change is wrong — never update it to make the suite pass. The tricks pref is held to it: absent, off, or on with no trick known, the 15 states read as before, and with every trick known the only characters that move are an `u` or an `s` becoming `t`. An intended change (a rule ported from upstream, a pack fix) updates it in the same commit, and the commit message names each marker that moved and the upstream source of its rule.
