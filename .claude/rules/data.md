# Game data and logic (`apps/web/src/games/alttpr/data/`, `apps/web/src/games/alttpr/logic/`)

ALttPR's modules live under `apps/web/src/games/alttpr/`: a short path below (`logic/…`, `stores/gameStore.ts`, `map/…`, `autotrack/follow.ts`) is relative to it, unless it names one of the shared modules (`components/ui/` Modal, Tabs, ConfirmDialog, ToolbarMenu, ToolbarIcons, UpdatePrompt, Header; `autotrack/guide.ts`, `autotrack/status.ts`; `hooks/` useGridNavigation, useNow, useToolbarFit, useTooltip; `stores/` tooltipStore, updateStore; `utils/`; `styles/`).

The rules are the alltpr pack's (`packs/alttpr`, ALttPR v31): the app holds no predicate of its own. It reads the pack through `apps/web/src/games/alttpr/logic/`:

- `logic/settings.ts` — what the app's run types mean to the pack (`packSettings`, a hidden setting passed as the pack's `UNKNOWN`: NoGlitches and randomized weapons in the Open, Standard or Inverted world (`worldOf` names it, the key of what is kept per world), with the run's goal, crystals, swords, item placement, accessibility, item pool and functionality, its dungeon items (`dungeonItems`: standard, mc, mcs or full, which of them may leave their dungeons)), the grid's dungeon indices (`dungeonAt`, `dungeonName`, by the pack's `LEGACY_DUNGEONS`) and where each dungeon counter starts (`counterMax`, from `dungeonItemCount`).
- `logic/packItems.ts` — `PACK_ITEMS`, the one table from each of the tracker's item ids to what its value records for the pack (an item and how it counts, a dungeon beaten, a prize, nothing). `packReading` reads a run through it and `itemsFromPack` turns pack item counts (an autotracker's reading) back into the tracker's values. `RECORDED_LEVELS` lists every pack item the cells can record, at the highest level they reach: what the blockers may propose. An item added to `data/items.ts` gets its entry here, and every reader picks it up; its spec holds the table to the pack's legacy copy for the version 5 ids.
- `logic/solution.ts` — the run solved: `trackerInput` reads the store's items (through `packReading`), pads and keys as the pack's `TrackerInput`; `solutionOf` runs `toState` and the key model (`solveWithKeys`) in the world compiled once per settings, memoized on the four slices it reads and the events checked (the pack's `EVENT_CHECKS`: the Bomb Merchant, whose big bomb Inverted's Pyramid Fairy wants), with no second store. A `crossedLogic` run takes its tris from the entrance randomizer's world for the entrances noted (the `entrances` slice joins the memo), once `logic/crossed.ts` is loaded (`hooks/useCrossedLogic.ts`, both views; `setCrossedSolver` sets the store again so every selector solves anew), every check maybe until then; its go mode steps through that world, and so does its analysis (`analyzeFacts`, through the lazy solver). The solution keeps each location's tri and what can be seen of it (the engine's visible channel). Markers and dungeons read it through `markerStateOf` (`locationStatus`: available > possible > seen > unavailable, seen being out of logic but in sight), `dungeonStateOf` (the pigeonhole rule over a counter), `bossStateOf` and the hooks `useLocationStatus`, `useMarkerStatus`, `useDungeonStatus`, `useBossStatus`, which return strings so a click re-renders only what it changed. `locationStateOf` is one location's: done once checked.
- `logic/checks.ts` — the Checks list's model: `zonesOf` groups the map's locations by zone in upstream's world order (a dungeon's under its name, Hyrule Castle for upstream's Escape; any other under its region's), memoized per world; `checkStates` says what each shows, every check of a dungeon whose counter is 0 done.
- `logic/missing.ts` — what each check not in logic is missing and the go mode's blockers (`analyzeRun`: the engine's `analyze` and `explain` in the state with every untracked key held, proposing only `RECORDED_LEVELS`; for a `crossedLogic` run, `analyzeCrossed` over the entrance randomizer's world, its facts read through as the items that bring them), and `goModeStatusOf`, memoized on the solution. `analyzeRun` costs milliseconds for the world, so it never runs on a click: `hooks/useRunAnalysis.ts` schedules it at idle into `stores/analysisStore.ts`. Over that analysis, `groupMissing` (pure, nothing solved) groups checks that miss the same thing (the same ways and kinds of doubt: out of logic first), `compactSpots` folds the checks of one room into the room with a count, and `dungeonMissing` applies both to a dungeon's checks and its boss.
- `logic/timeline.ts` — when each thing held was found: the `Stamp` of a change (`stampOf`, read off the run timer of `apps/web/src/utils/runTimer.ts`), `stampTimeline` (what a change of the run's items and checks adds to or drops from the timeline; the same object when nothing dated changed), and what a save's timeline may hold (`isTimelineKey`, `isStamp`). The store keeps it in `Progress` (`.claude/rules/store.md`).
- `logic/voice.ts` — the voice commands: every phrase (`COMMANDS`, built from the shortcut controls `CONTROLS` with the words players say them by) and what it does, the recognizer's grammar (`GRAMMAR`: each phrase after the wake word `tracker`, then `[unk]`), `commandsOf` (a recognized text's commands, none without the wake word) and `changedValue` (a find, not a click: a toggle held, a level up never round to none, a bit added, a named level never lowered, a dungeon count down never below none). Its words must be in the speech model's dictionary (vosk-model-small-en-us-0.15): a name it lacks is spoken as words it has ("samaria", "bom boss", "gannon tower"). Adding a control to `CONTROLS` fails its spec until a phrase reaches it.
- `logic/crossed.ts` — the logic of a `crossedLogic` run, loaded on demand: the pack's `erWorld` for the run's settings and `crossedConnections` of the entrances noted (a door not noted leads nowhere), built again only when either changes, solved with `solveFactsState` (a `CrossedRun`: the world, the state with its facts, the solution), its go mode (`goModeStatusBy`) and its analysis (`analyzeFacts`). Anything that reads that world goes through it, so its rules stay out of the main bundle.
- `logic/entrances.ts` — the entrance assistant's model over the pack's entrance tables (`entrances.ts`): the run's shuffled pool (`poolOf`: Open or Standard crossed; none for Inverted, whose tables are not ported), what an entrance may lead to (`targetsFor`, the pack's `targetsOf`), what noting one notes (`notesFor`: a hole with its cave's door), what the doors autotracking shows Link went through note (`gameNotes`: the pack's `linksOf` within `targetsOf`, of rooms alike the one noted there or else one noted nowhere), where each entrance's marker is drawn (`layoutEntrances`, `layoutOf`: its door's spot, pushed clear of neighbours that would hide it, at most 3.5% of its world away), where the map's markers stand (`placeMarkers`: a marker wholly inside one place, by the pack's `PLACE_OF_LOCATION`, above the first door noted to lead there, nowhere until one is) and their words. Only the assistant's lazy components and autotracking's follower (`autotrack/follow.ts`, in a run whose entrances it knows) import it, on demand, so a run without shuffled entrances never loads the tables.
- `logic/needs.ts` — the engine's blockers in the tracker's words: each atom as the name and icon the player knows (`waysOf`, `sameWays`).

`apps/web/src/games/alttpr/data/`:

- `items.ts` — `ItemState`, `itemGridFor` (the grid of a run: a retro run's last row holds the shops, `shoparrow` and `shopkey`, where Hyrule Castle's and Castle Tower's key cells stand), and one `[min, max, initial?]` range table from which `items`, `itemsMin` and `itemsMax` are derived, plus `itemLabels` for accessibility names. Do not reintroduce parallel tables. The ids are the tracker's own, which `logic/packItems.ts` maps to the pack's (old saves go through the pack's frozen legacy copy, which `legacy.spec.ts` holds the table to): a dungeon counter's top follows the run's settings (`itemRange` in `stores/persistence.ts`), and `agahnim2` (Ganon's Tower's boss, on its map marker and its grid cell) is the one id version 6 added; `chest12` (Ganon's Tower's items left) came with its cell. `magic` (0 none, 1 half, 2 quarter, as the pack counts it) is a cell that toggles (`TOGGLE_ITEMS`); the logic reads its real value.
- `keymap.ts` — the keyboard shortcuts, as plain data. The default keys follow the grid's item block; the items beside it keep a key each (`BESIDE_BLOCK_KEYS`), whatever the grid's order, so no key changes hands when a cell moves. A keymap saved before a cell existed gets its keys in a `migrate` step (`migrateV11`: the half magic's Slash), never moving a chord the player holds.
- `presets.ts` — run types (`getPreset`, `presets`, `describeSettings`, which says "?" for a hidden setting). `entrancesKnown(settings)` says whether the assistant knows a run's shuffled entrances (Open or Standard), without loading the tables. `logicModelled(settings)` says whether the pack models a run's rules: vt's without shuffled entrances, the entrance randomizer's for `crossedLogic` runs (the crossed shuffle in the Open or Standard world with `full` dungeon items, Crosskeys'); when it does not, `solutionOf` makes every location maybe, the go mode and the analysis say nothing, and the picker marks the run type "logic soon". Mystery starts with every `HIDEABLE` setting hidden: the goal, the swords, the crystals, the item placement, pool and functionality, and the accessibility, those the pack can leave unknown. The world names a run type, and the dungeon items are assumed until set, since the key model and the counters rest on them. `TUNING` gives each `TunableSetting`'s options, the dungeon items and the goal (but Triforce Hunt, a run type of its own) included.
- `apps/web/src/games/alttpr/constants/index.ts` holds only values with game meaning.

## Rules are ported, not remembered

A rule changes in the pack, ported from the randomizer's own source (sporchia/alttp_vt_randomizer at the commit `packs/alttpr/upstream.json` pins) and held to its official tests: see `.claude/rules/pack.md`. The app maps settings and what the player records; it never re-spells a rule.

## Refactor guard

`logic/alttpr.snapshot.spec.ts` freezes what the map shows (every marker, every dungeon's counter and boss) across 15 item states, those the 2017 logic's characterization spec froze. If it moves without an intended rule change, the change is wrong — never update it to make the suite pass. An intended change (a rule ported from upstream, a pack fix) updates it in the same commit, and the commit message names each marker that moved and the upstream source of its rule.
