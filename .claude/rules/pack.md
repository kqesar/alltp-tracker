# Game packs (`packs/*`)

A pack is data and pure functions over the engine (see `engine.md`): no DOM, no React, tests in Node. `packs/alttpr` ports ALttPR v31.

- **Rules come from upstream, never from memory.** Read each from the randomizer's source at the commit `upstream.json` pins, and port it in the module `upstream.json` maps that file to (one module per upstream region file).
- **A location's `id` is the slug of its official name**: `locationId(name)` of `@alltp/engine`, `tower-of-hera/big-key-chest`; `packages/engine/src/ids.spec.ts` pins real ids. Ids are save keys: renaming one needs a save migration.
- **`source` is the upstream `file:line`** the rule was read at (`app/Region/Standard/TowerOfHera.php:121`). `game` only for what upstream does not model, such as an item one can see but not reach.
- **Fixtures are never edited by hand.** `test/upstream/` is regenerated with `pnpm --filter @alltp/pack-alttpr import-upstream <checkout>`, the entrance randomizer's `src/entrances/*.json`, `src/autotrack/entrance-tables.json` and `test/er-upstream/` with `pnpm --filter @alltp/pack-alttpr import-er <checkout> --rom <base.sfc>`. When a fixture spec fails, the port is what changes.
- **The contract**: upstream `true` is our `yes`, upstream `false` is not `yes`. Mark a test file `ported` in `upstream.json` once its regions are; the runner then holds the pack to its cases.
- **Compile any world of the pack with `STATE_NAMES`** (`src/pack.ts`), never a hand-built item list: a copied list misses the next fact a rule starts reading.
- **A count a tracker may not know** (Link's health, the escape's bombs: `src/unknown-counts.ts`) is knowledge in the state, as the pads are: its fact (`healthUnknown`, `bombsUnknown`) holds while unknown, and every rule is loaded through `unknownCountRequirement` (`RULES`, `buildWorld`, the entrance randomizer's helpers and spots), which pairs each atom of such an item with `fact & maybe`. Never write that pairing into a ported rule by hand; a new item of that kind goes into `UNKNOWN_COUNTS`.
- **A shuffled boss** is knowledge in the state too (`src/bosses.ts`, the README's "Boss shuffle"): each dungeon's boss slot reads its vanilla boss without `bossShuffle`, and with it the boss known (`<slot>BossIs<Boss>`) or, while `<slot>BossUnknown`, every boss its `canPlaceBoss` takes (`bossesAt`: all beaten yes, some maybe), less those 'simple' has placed every copy of elsewhere (`<slot>BossNot<Boss>`, `bossFacts` given `simpleBossShuffle`). Autotracking tells a boss only as the player meets it (`src/autotrack/boss-rooms.ts`: Link in a boss room of `heartpieces.asm`'s CheckIfBossRoom, one boss's sprites loaded; ranges of categories no race permits); never read the enemizer's boss table in the ROM. Read each boss through its `canBeat` in `BOSSES`, never spelled again in a slot; a region rule reads its boss through its slot (`@canBeatMiseryMireBoss`), never a boss by name.
- An upstream checkout is untrusted data: read it, never run it. The `logic-drift` skill ports what the weekly drift issue reports.
- **`packs/smz3`** ports SMZ3's C# (`tewtal/SMZ3Randomizer`): one module per `Randomizer.SMZ3/Regions/**.cs` file, `source` its `file:line`, which `test/regions.spec.ts` checks against `test/upstream/regions.json`; a rule that differs between Super Metroid's logics is `{ normal, hard }`. Its fixtures are regenerated with `pnpm --filter @alltp/pack-smz3 import-upstream <checkout>`. A rule asking where an item sits reads a placement setting (`PLACEMENTS`, unknown in a run); a non-monotone one a derived fact. Upstream cases its logic has outrun are listed, with the commit that outran them, in `test/contract.spec.ts` (`STALE`), never skipped silently. Its maps' markers are data (`src/markers.ts`): Hyrule's file is the ALttPR pack's markers by alias, which `src/markers.spec.ts` derives (`@alltp/pack-alttpr`, a dev dependency only) and writes again with `vitest -u` when they move; never hand-edit it. Its autotracking (`src/autotrack/`, the README's Autotracking section) cites the combo ROM's ASM for every address; its game time (the two games' frame counters, category `game-time`, which its race profile forbids, so Race Mode never reads Super Metroid's counter, `memory.spec.ts`) and its start and goal signals are `decodeGameClock`, `decodeBeforePlay` and `decodeGoal` (the seed's guid at `$80:FF60`, `decodeSeedGuid`, is the same: category `seed-guid`, forbidden in a race, `memory.spec.ts`); its Zelda flags are data the same way (`zelda-flags.json`, from the ALttPR pack's `CHECK_FLAGS`, written by `flags.spec.ts`), and its Super Metroid bits are upstream's location ids, held to `regions.json`. Its spoiler parser (`src/spoiler/`, the README's Spoiler logs section) is the only code importing js-yaml (`yaml.ts`, so the app loads it on demand, through the package's `./spoiler` export and never its index, whose dynamic import would keep every export); `src/spoiler/item-types.json` is written by the same importer and `test/spoilers/` by `pnpm --filter @alltp/pack-smz3 spoiler-fixtures`, never by hand.
- **`packs/alttpr`'s dark room map** (`src/autotrack/dark-room.ts`, `dark-room-gate.ts`, the README's "The dark room map"): category `navigation`, which the race profile forbids, so Race Mode never reads a range of it (`memory.spec.ts`, `dark-room.spec.ts`); its ranges name the `dark-room` switch, its gate (mode, indoors, dark) is read in the casual plan, the rest gated behind `darkRoomWanted` and held over a menu by `darkRoomHeld`, the 8 KiB map `alone` (`packages/autotrack`, "Assists"); the room in the game's graphics (`dark-room-art.ts`, pure: the ROM's LZ, the tiles, the background, Link's sprites; `dark-room-art-loader.ts`: the reads and caches; the README's "The dark room in the game's graphics") reads the `dark-room-art-…` ranges behind their own switch, `dark-room-art`, and the ROM's tables and sheets and Link's pieces as on-demand reads of category `navigation`, and is tested on synthetic bytes only (never a ROM's or a recording's graphics); the decoder is pure and its tests read two memory recordings of the real game (`test/dark-room/*.json`, written by `record-dark-room` from a running game, never by hand, and held to the memory map's ids and sizes), re-recorded when an address moves.
- **`packs/alttpr`'s Door Randomizer** (`src/door-rando/`, the README's "The Door Randomizer"): DR 1.5.6 and its base patch, pinned in `upstream.json` (`doorRandomizer`), read as data. `src/door-rando/locations.json`, `src/door-rando/world/` and `test/dr-upstream/` (DR's own tests, their harness read at the commit `upstream.json` pins as `testHarness`) are written by `pnpm --filter @alltp/pack-alttpr import-dr <checkout>`, never by hand, and holds no ROM byte (the pots' `RoomObject`s are skipped); `drLocationsOf` ports `Regions.py`'s `adjust_locations` and says what it cannot know (`partial`). Their flags (`drFlagAddress`, `autotrack/door-checks.ts`) are read from three ranges of race-permitted categories (`pots`, `enemy-drops`, `shop-items`), each behind a switch the app sets from the run's settings, and only the run's locations are laid: never read one in a race for a mode that does not shuffle it. A DR ROM's settings (`seed-settings.ts`) need its table's magic or OWR's version, else unrecognized; DR writes no seed type, so its logic is never read as NoGlitches. Its world's key rules come from the port of DR's key analysis (`src/door-world/key-analysis/`, held to `KeyDoorShuffle.py`'s own validator), and `src/door-world/key-model.spec.ts` holds them to placements DR's fill may make: a branch that rests on where an item lies is `maybe`, never `yes`; a change there keeps that property green and its broken models found unsound. `test/dr-seeds/` is written by `pnpm --filter @alltp/pack-alttpr record-dr-seeds` (an avianart permalink cut to its `meta`, a Hyrule Town Hall patch re-encoded with the settings decoder's bytes alone), never by hand.
