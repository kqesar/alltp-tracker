# Tests

- **Assertions must be able to fail.** This codebase once asserted `expect([all four states]).toContain(result)` and had "keyboard navigation" specs that pressed no keys. Never guard an assertion with `if (found.length > 0)`: a query that finds nothing must fail. When fixing a bug, check the new test fails without the fix.
- **Locate with `data-testid`** (`getByTestId`, `getAllByTestId(/^marker-/)`), not CSS classes, inline styles or positions in `getAllByRole("button")`. Ids are kebab-case `<kind>-<id>`: `item-hookshot`, `marker-kings-tomb` (a map marker, by the pack's id), `boss-marker-eastern-palace` and `dungeon-marker-eastern-palace` (a dungeon's, by the pack's dungeon id), `chest-overlay-0`, `medallion-overlay-8`, `import-file`. Then assert accessibility on the element found (`toHaveAccessibleName`, role) so the test still covers what a screen reader hears.
- **Reset the store** in `beforeEach` with `useGameStore.setState(useGameStore.getInitialState(), true)` (and `localStorage.clear()` when persistence matters). Two specs mock `@/games/alttpr/stores/gameStore` entirely with a selector-calling `vi.fn()`; keep their fake state in step with the store's fields.
- **Autotracking specs** share the session's fakes from `apps/web/src/autotrack/fixtures.ts` (a status of each code, `ManualClock`, `FakeVisibility`, `FakeLocks`, `GRANTED`); a game's console memory is its own: ALttPR's in `games/alttpr/autotrack/fixtures.ts`, Super Metroid's `writeMapRando` in `packs/sm/test/sm-rom.ts`. Browser tests drive the real WebSocket through `packages/autotrack/test/fake-usb2snes.ts`.
- **Dark room specs** read memory recorded from a running game (`packs/alttpr/test/dark-room/*.json`: the ranges' bytes, with how they were read in `description`), put into a console image by `putDarkRoom` (`games/alttpr/autotrack/fixtures.ts`), and drive the real session over `MemoryTransport` or, in `e2e/dark-room.e2e.ts`, the fake usb2snes bridge. Never edit a recording by hand: record it again with `pnpm --filter @alltp/pack-alttpr record-dark-room` from a game in the room (its header says how a room loads dark by the game's own code). A spec that needs another state patches the image in the test. The room in the game's graphics is tested on synthetic bytes only, never a ROM's or a palette's: `putDarkRoomArt` (the same fixtures) lays a guard, tables, sheets that unpack to stripes, a palette and one sprite of Link's into the image, and the pack's specs build their streams and tilemaps by hand.
- **Review specs** read the real spoiler logs the ALttPR pack records (`packs/alttpr/test/spoilers/`) through `games/alttpr/review/fixtures.ts` (`?raw` imports: the app has no Node types); jsdom's `File` reads them, and a fake `ReviewWorker` (`review/read.ts`) stands in for the real worker, which `apps/web/e2e/review.e2e.ts` drives. A run to review is built from the log, never from a player's own run: `playedRun` (the same fixtures) stamps a plan of places through the store's `stampTimeline`, each check and its item at one instant as autotracking does; the browser test plays one in the page, clicking a marker and its items with the clock paused, then resumes it (the sweep runs on the page's timers). A spec that proves the review never reaches storage, an export or a link compares them before and after an import.
- Super Metroid's review specs read the real Map Rando log the SM pack keeps (`packs/sm/test/spoilers/`, cut to the keys read) through `games/sm/review/fixtures.ts`; `e2e/sm-review.e2e.ts` builds a 21 MB log from it (the heavy keys the real file has, padded with strings that hold brackets and quotes) and reads it through the real worker, asserting a worker did and the page kept drawing.
- **SMZ3 review specs** read the pack's recorded samus.link log (`packs/smz3/test/spoilers/`, the Download's text rebuilt from the API with the site's code, its provenance says so) through `games/smz3/review/fixtures.ts`; the ALttPR log stands in for "another game's".
- **Archipelago specs** run the real archipelago.js. Answers come from recorded AP 0.6.8 frames (`packages/archipelago/test/responder.ts`, over `test/fixtures/`, which are re-recorded, never edited): in memory under a `ManualClock` through `test/fake-socket.ts`, or over Node's WebSocket through `test/fake-ap-server.ts` (`ws`), which can refuse, hang at each stage or cut the connection. `test/real-server.spec.ts` is skipped unless `AP_SERVER_URL` points at a real server hosting `test/server/normal-seed4242.archipelago`. The board's specs reach the same in-memory room through `apps/web/src/games/archipelago/fixtures.ts` (`startRoom`, `playOn`, `alttpNames`), which imports the package's helpers by a computed address (they read the fixtures with Node, which the app's types do not know) and types what it uses; its browser test starts `test/fake-ap-server.ts` itself. IndexedDB is `fake-indexeddb`'s, one `IDBFactory` per spec.
- **The `web` project runs in `vmThreads`**: one jsdom per worker, a vm context per file (a third of the CPU saved). `window.location` cannot be replaced there, as in a browser: reach what a spec must fake through a seam (`page.reload` in `components/ui/lazyDialog.tsx`, `switchGame`'s `reload` parameter). Code runs slower in a vm context, so the timing specs (`*.performance.spec.ts`) are the `web-perf` project (`apps/web/vitest.perf.config.ts`, `forks`); a new timing spec takes that suffix. Both projects share `apps/web/vitest.shared.ts`.
- jsdom has `<dialog>` but not `showModal()` / `close()`; `apps/web/src/test-setup.ts` stubs them by toggling `open`. Escape is simulated by dispatching a cancelable `cancel` event on the dialog.
- `apps/web/src/games/alttpr/logic/alttpr.snapshot.spec.ts` is a refactor guard (see `.claude/rules/data.md`): never update it to make the suite pass.
- **Browser tests** live in `apps/web/e2e/*.e2e.ts` (Playwright + `@axe-core/playwright`, Chromium, production build under `/alltp-tracker/`). One page load per width carries every check for that width, to keep the run short. A known defect is pinned with `test.fail(condition, reason)`: the test turns red the moment the defect is fixed, so the fixing commit must drop the marker. CI runs them parallel to the unit tests, split over three runners (`--shard`, the count set by the matrix in `ci.yml`; one runner's cores are saturated by two browsers, so more workers do not help), on the runner's preinstalled Chrome. Locally Playwright runs its headless shell, CI that Chrome in Chrome's own headless mode: they differ where the browser decides for the player (Local Network Access: the shell keeps a refused permission `prompt`, Chrome reads it `denied`), so a test that depends on such a decision runs Chrome's mode locally too (`channel: CI ? "chrome" : "chromium"`, as `archipelago-self-hosted.e2e.ts`).
- Coverage thresholds in the root `vitest.config.ts` (measured over every workspace) are floors just below current coverage; raise them when coverage rises.
- **Door Randomizer specs** read the seeds `packs/alttpr/test/dr-seeds/` records (`record-dr-seeds`: avianart `meta`, a Hyrule Town Hall patch cut to the settings' bytes, which `seed-import.spec.ts` holds to them), and build a DR ROM's tables by hand at the offsets DR's `Rom.py` writes (`seed-settings.spec.ts`, `readout.spec.ts`), its pots' and drops' bits in WRAM bank $7F (`door-checks.spec.ts`, `apply.spec.ts`).
