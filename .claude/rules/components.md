# UI, styles and accessibility

ALttPR's modules live under `apps/web/src/games/alttpr/`: a short path below (`logic/…`, `stores/gameStore.ts`, `map/…`, `autotrack/follow.ts`) is relative to it, unless it names one of the shared modules (`components/ui/` Modal, Tabs, ConfirmDialog, ToolbarMenu, ToolbarIcons, UpdatePrompt, Header; `autotrack/guide.ts`, `autotrack/status.ts`; `hooks/` useGridNavigation, useNow, useToolbarFit, useTooltip; `stores/` tooltipStore, updateStore; `utils/`; `styles/`).

## Components

- `tracker/` — `TrackerGrid` → `grid/GridItem` routes a cell: empty → spacer, `keysN` → `BigKeyCell`, the key cell of key dungeon N (`KEY_DUNGEONS` in `logic/settings.ts`: the grid's ten, then Hyrule Castle, Castle Tower and Ganon's Tower on the 8th row) (`KeyToggle` buttons for what its pool holds, `ownItems`: the big key and the small keys, none for Eastern Palace, whose pool has no small key, no big key for Hyrule Castle or Castle Tower; in runs whose maps and compasses leave their dungeons (MC, MCS and Full Shuffle: `wildItems` in `data/presets.ts`) only, the map and compass on top, the small keys' count then a badge on the key), `keylabelN` → `KeyLabel` (a castle dungeon's short name, HC and GT, as keysanity trackers label their key rows; decorative: Castle Tower has Agahnim's cell, `agahnim`, in its place, a cell that stays when the key cells go), the half magic a plain `Item` between the tunic and the boots (`magic`, in `TOGGLE_ITEMS`: its click toggles none and half, whatever the value, and a quarter magic read from the game is kept for the logic and drawn, named and stepped as the half), in a retro run no small key (generic keys are no dungeon's) and, on the 8th row, the shops' cells (`itemGridFor`), the key cells' rows showing only with the key cells (`visibleRows`; `layout--key-rows` sizes `--cell` for 8 rows), `boss*` → `BossCell` (a `<fieldset>` named after the dungeon: the boss button plus `MedallionPicker`, `ChestCounter`, `RewardPicker` as sibling buttons from `overlays/BossOverlays.tsx`; Ganon's Tower's, `boss12` at the end of the 8th row, which therefore always shows, holds Agahnim 2 (`agahnim2`) under its short name, GT (decorative, so its Agahnim is not taken for Castle Tower's), and its items left (`chest12`, up to 27: the `chestN.png` counters run to 27) and no reward), else → `Item`.
- Every grid control spreads `useGridFocusable({ row, col, slot })` (roving tab index, arrow-key position; slot 0 is the cell's main control, then reading order) and `useStepHandlers(step, useControlShortcuts(control).aria)` (click forward, right-click or "-" back, touch long-press ignored; `aria-keyshortcuts` lists the control's keyboard shortcuts and "-"). Never put a button inside another.
- Keyboard shortcuts: `hooks/useItemShortcuts.ts` is the one window listener; a bound key steps its control through `stepControl`, exactly as a click does. It shares `isAwayFromBoard` (`apps/web/src/utils/keyboard.ts`: typing in a field, a dialog open) with `games/useUndoShortcuts.ts` (one hook, given each game's store), skips IME composition and auto-repeat, and never takes a Ctrl/Cmd chord or a key that keeps its own job (`refusalOf` in `data/keymap.ts`). The focused cell's "-" gives way to a shortcut on the same physical key.
- `map/MapTracker.tsx` draws two square worlds (`map-world-light` / `-dark`), side by side, stacked or `auto` (stacks below 35rem via a container query). Coordinates are authored against the whole asset and placed in their world by `toWorldPosition` (`apps/web/src/utils`): the alltpr pack's markers are in that space (percent of the whole image). It draws the run's world's (`markersOf`): an Inverted run moves Link's House to the Dark World, puts the Bomb Merchant in its place and swaps Castle Tower's and Ganon's Tower's doors.
- `map/MapMarkers.tsx` — `MapLocation` (one location or a cave's several: a click checks them all, or none once all are) and `MapDungeon` (a decorative, `aria-hidden` square showing the counter by the pigeonhole rule, under the boss button, which toggles the boss's grid flag) are `<button>`s named by the marker's name plus their state, with a glyph per state besides the colour: ✓ available, ? possible, an eye (a CSS mask, since emoji fonts colour the character) for seen — out of logic but in sight, from the engine's visible channel —, ✕ out of logic. The precedence is `locationStatus`'s: available > possible > seen > unavailable. They read their state through the hooks of `apps/web/src/games/alttpr/logic/solution.ts` (`useMarkerStatus`, `useBossStatus`), which return strings, so a click re-renders only the markers it changed. Markers keep a 24 px floor; where real locations sit closer than that, WCAG 2.5.8's map-pin exception applies and the e2e target-size check skips `.mapspan`.
- `map/MapPanel.tsx` — the map panel: ARIA tabs Map | Checks | Run, with Entrances after Checks while entrances are shuffled (`ui/Tabs.tsx`) over one tabpanel, `#map-view`, which shows the worlds and their legend, `ChecksPanel` or `RunPanel`, by the `mapView` preference; `VoiceControl`, `RunTimer` and `GoMode` sit beside the tabs (`map-panel__status`). Over the map and the checks, `LogicNote` says why every check is maybe while the run's logic is not modelled (`logicModelled`), and in a `crossedLogic` run that the logic follows the entrances noted. "Skip to map" and "Skip to checks" render their view with `flushSync`, then focus `#map-view`.
- `map/entrances/` — the entrance assistant, for a run with shuffled entrances, each module loaded on demand with the pack's entrance tables (`logic/entrances.ts`): `EntranceLayer` (a shuffled world's markers, each check inside a place the shuffle mixes standing above the first door noted to lead there or nowhere yet (`placeMarkers`; the Dam's, half outdoors, stays), then its shuffled doors and holes as round `mapspan` buttons; pointing at a noted one rings every entrance into the same place (`entrancePickerStore.linked`); an empty dashed ring while not known, filled by the kind of place once noted with a glyph for each, named "Kakariko Shop: leads to Elder House (East)", with a `text` tooltip), `EntrancePicker` (the `Modal` "Where does … lead?": a search, then the targets the shuffle may give it by kind as buttons (`targetsOf`), a hole and its cave's door noted together as one step (`notesFor`, `noteEntrances`); one noted elsewhere says where, and choosing it moves it; "Not known" forgets one) and `EntrancesPanel` (the Entrances tab: every entrance by world, its destination beside it, a search, how many are noted and that autotracking notes each door gone through outside Race Mode). The markers and the list open the picker through `entrancePickerStore`.
- `map/ChecksPanel.tsx` — every location of the map's markers as a list, by zone (`logic/checks.ts`: a dungeon's under its name, any other under its upstream region's). Status filters with their counts (available and possible shown at first), a zone `<select>` and a search narrow it, and a `role="status"` summary says how many rows show. A row is a checkbox calling `toggleChecks([id])`, its state in words beside the map's glyph (`check-swatch state-glyph`), and for a state other than available or done a "Why?" disclosure with `MissingLines`, mounted only once opened, and only while the run's logic is applied (`solutionOf(…).modelled`: not while a crossed run's logic loads). A dungeon whose counter is 0 shows its rows checked and disabled. The panel subscribes to every state at once (`checkStates` through `useShallow`) and rows are memoized; a row a filter hides once ticked hands its focus to the next row. Zone headings are sticky and take the page's fixed background (`.page-background`). Beside the grid it scrolls inside the viewport's height; under it, it grows with the page.
- `map/RunPanel.tsx` — the Run tab: the run at a glance (`<dl>`: the timer's time, ticking only while it runs; the checks done, `checkStates`; the bosses beaten), the splits (a `<table>`: the bosses in the order they fell, from `splitsOf` in `logic/runLog.ts`, each with its time and the segment since the last, then the goal once the timer stopped there), the timeline (an `<ol>`, newest first: each find's `<time>`, or a dash said as "before the timer", its sprite as the board draws it, `findIcon`, and its name, `findName`; rows memoized) and "From the game", the ROM's own stats (`reading.progress.romStats`, in the end credits' order) outside races once a file is loaded, or why not. Beside the grid each column scrolls inside the viewport's height; under it, the panel grows with the page. It reads the timeline (`logic/timeline.ts`) with one selector.
- `map/GoMode.tsx` — the run's go mode (`goModeStatusOf`): ☆ not yet, ★? possible, ★ in logic, with its words; hidden for a goal without one, and a plain label "Go mode: goal unknown" while a Mystery run's goal is hidden. It is a button opening a popover (the Popover API, placed under it on click) with what the go mode is missing (`useGoModeMissing`, `WaysList`); a visually hidden `role="status"` announces a change.
- `map/RunTimer.tsx` — the run timer (`timer` in the store, `apps/web/src/utils/runTimer.ts`), drawn by the shared `components/ui/RunTimer.tsx` (which Archipelago's, Super Metroid's and SMZ3's boards draw too, over their own stores and words; the last two through `components/ui/GameRunTimer.tsx`, given a store hook and whether Race Mode is on and the game's clock was read): a button showing the time (tabular figures) and the state's glyph (▷ not started, ▶ running, ❚❚ paused, ✓ stopped at the goal) with the time and its words in the accessible name (Label in Name: the visible text is part of it), opening a popover like `GoMode`'s (`placeUnder` in `apps/web/src/utils/popover.ts`): the time as `role="timer"`, Start / Pause / Resume, Reset, the `autoTimer` checkbox ("Start and stop with the game") and the clock choice (the shared component's optional `clock` prop, which Archipelago's board omits as a room has no game clock: a `<fieldset>` with the legend "Clock", two radios, Real time and Game time, and a hint under them that describes the fieldset; Game time is disabled with its reason in Race Mode, where the checked radio reads Real time; while the game's clock sets the timer (`following`: Game time, not Race Mode, a reading with a file loaded) Start, Pause and the checkbox are disabled). Outside Game time, outside Race Mode while the game is in play, the panel also gives the ROM's own play time (`romStats.playFrames` → `playTimeMs`); while Game time follows it the line would repeat the timer, so it goes. Only it re-renders each second, and only while running (`hooks/useNow.ts`, ticking on the second's boundary); a visually hidden `role="status"` says a change of state, never the ticks.
- `map/VoiceControl.tsx` — voice commands: `VoiceControl`, a button beside the run timer whose words and microphone icon say the status (in sight for as long as the tracker listens; a command heard shows on it for 3 s, "…: no change" when it changed nothing), opening a `Modal`: what voice commands do and that no sound leaves the computer, the status with what to do on a failure, the microphone (`enumerateDevices`, listed again once listening has named them), Start / Stop listening, and "What to say" (`VOICE_GUIDE` of `logic/voice.ts`, phrases in `<q>`). `VoiceLiveRegion` says each command heard. The engine (`voice/engine.ts`: Vosk in a Web Worker, an AudioWorklet handing the microphone's samples on, the model kept in IndexedDB) is a chunk of its own, imported when listening starts; `voice/apply.ts` does what a command says through the store (`setItem`, `setSmallKeys`, `handleMedallionChange`, undo, redo, the timer), leaving a control the board hides alone (`isControlShown`, shared with the shortcuts).
- `ui/Missing.tsx` — the words of what a check is missing: `MissingLines` ("Missing", "In logic with", "Possible with", "Maybe" lines), `WaysList` (each thing with its icon; "a door you have not noted" for `Ways.door`, what no item brings in a crossed run), `doubtText`. The tooltip and the Checks list's "Why?" share them.
- `ui/Tooltip.tsx` — the page's single tooltip, driven by `stores/tooltipStore.ts` (kept out of the game store so hovering never re-renders the board). Controls opt in with `useTooltip({ kind, … })`: mouse hover, keyboard focus, or a touch long-press (a tap stays the control's action). A map marker's (`kind: "marker"`, or a grid boss cell's `kind: "dungeon"`) lists each location it stands for with its state, and what one not in logic is missing (`MissingLines`, read from the run's analysis, never worked out on hover); a dungeon's says the items its counter has left and how many are surely in logic. The marker's accessible name says its state, so the tooltip is `aria-hidden`. When several hooks give one element the same handler, combine them with `mergeHandlers` (`apps/web/src/utils/mergeHandlers.ts`), never by spreading twice.

Live follow on the local network (`docs/desktop.md`, "Live follow on the LAN"): `liveFollow.ts` (`useLiveFollowStore`: the relay's session through `follow_start`, `follow_stop`, `follow_state`, the `follow-viewers` count; `attachFollow` picks up a relay still running after a reload; the page's run goes out through `runFeed.ts`) and `LiveFollowSection` (the Share dialog's "Follow live on this network" section, lazy: a `switch`, the live link's `QrCode` and address with Copy, the devices following in a `role="status"`, the same-network, firewall and auto-lock hints).

The run timer reads `utils/clock.ts` through `useNow`: the player's clock in that view, the device's elsewhere.
- The toolbar folds by measured fit, never by breakpoint: system fonts differ between macOS, Windows and Linux. `hooks/useToolbarFit.ts` lays a hidden copy of the bar out in each form (`FITS`, richest first) and writes the richest that holds — the full bar on one row, a folded one on two — to its `data-fit`, and what it folds to `data-fold` tokens, which `ui.css` and `styles/toolbar-menu.css` follow. The fold order: the secondary actions (Export, Import, Share, Stream view, Shortcuts) lose their labels first (`secondary-icons`: Mode, New game, Autotracking and the map layout keep theirs, so a button added later costs this step a few pixels, not every label), then every button does (`icons`), then the secondary actions go into More, then the map layout (`menuitemradio`s in a group), then New game to an icon, and last Autotracking into More (the first item there, its dot copied onto the More button); Mode and Undo/Redo never fold. More reads `data-fold` as it opens to know which settings it holds. The hook re-checks on resize, content change and font load, moves up only with 24 px to spare, and never re-renders React. Never key toolbar CSS on a viewport width. `StreamViewControl` and `ShortcutsButton` take `variant="menu"` to render as a menu item with their own dialog. React bubbles a portalled dialog's events through its React parents, so a menu item's dialog still reaches the menu's handlers: they act only on events from the menu's own DOM.
- Subscribe to the store with one selector per slice, never bare `useGameStore()`.

## Semantics and accessibility

- Every interactive element is a semantic `<button>` (or link) with an accessible name; never a clickable `div`, and never a button inside a button. A native button fires click on Enter and Space, so add no key handlers for them.
- Label in Name (WCAG 2.5.3, axe's `label-content-name-mismatch`): an `aria-label` starts with, or at least contains in order, the control's visible text, and axe reads the text of adjacent elements with nothing between them ("Autotracking" + "Off" is one word), so put a literal `{" "}` between the parts of a button or menu item that are separate elements (flex items draw no whitespace, so the look does not change).
- State is never conveyed by colour alone; give it text in the accessible name and a shape or glyph on screen.
- Landmarks and headings stay meaningful (`header`, `main`, labelled `section`s, one `h1`).
- Dialogs go through `Modal`; a destructive confirmation starts focus on the safe choice.

## CSS

- Shared styles live in `apps/web/src/styles/`, all imported by `styles/index.css`, which `main.tsx` alone imports. A game's own sheet (`games/sm/sm.css`, `games/smz3/smz3.css`) is imported by its `module.ts`, so it loads with the game, and so is `games/board.css`, what those two boards share (the panels of toggles `board-panel` and `toggle-chip`, the run type dialog's `mode-*` fields, `stream-url`, the grid cells' `board-grid__cells` and `board-cell__count`; the stream view's placement of `board-grid` is in `styles/obs.css`); the application menu's (`desktop/appMenu.css`) by `desktop/AppMenuItem.tsx`. `reset.css` stays first in that list.
- Class names are written literally in the JSX; there is no `CSS_CLASSES` map.
- CSS Grid for layout, never tables; a `<table>` is for tabular data only (the shortcuts list). Empty grid cells render a spacer rather than `null`.
- Colours, spacing and sizes come from the tokens in `variables.css`; respect `prefers-reduced-motion`.
