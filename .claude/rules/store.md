# State: a single Zustand store

All game state lives in `apps/web/src/stores/gameStore.ts`: `zustand` + `devtools` (development only) + `persist` (localStorage key `alltp-tracker-state`). The store holds only serializable data; the rules are the alltpr pack's, solved from it by a memoized selector (`apps/web/src/logic/solution.ts`), never kept in a store. Its shape is `Progress & Prefs` plus the undo history, both types declared in `apps/web/src/stores/persistence.ts`. Transient UI state lives in its own stores, never saved or undone: the tooltip (`tooltipStore.ts`), the run's analysis (`analysisStore.ts`: what every check and the go mode are missing, worked out for one solution when the browser is idle by `hooks/useRunAnalysis.ts`, and read only while that solution is on screen), the keyboard layout map (what each key types, for labels) in `keyboardLayoutStore.ts`, a waiting new version (`updateStore.ts`, which also registers the service worker), and autotracking (`autotrackStore.ts`: the one session per page, loaded lazily on Connect, its status and last decoded reading; only `connectOnStart` and `keptSeed` are saved, under `alltp-tracker-autotrack`; the stream view never connects). Each reading's seed is held against the board's run type before it is laid (`followSeed`, the words in `autotrack/seed.ts`): a seed of another run type switches a fresh board (`isFreshRun`) at once, once per page and never for a seed the player kept (`keptSeed`), and leaves `news` for the live region, said with the status it came with and once more with the next; otherwise `useSeedCheck` (derived from the reading and the board, never stored) feeds SeedPrompt, whose `switchToSeed` and `keepRunType` the player answers. A seed whose name (the header's) is an alttpr.com hash asks alttpr.com for its file once per connection (`seedFile`, transient: "loading", the settings or why none, from `autotrack/seedFile.ts`): it states what no ROM does (item placement, accessibility, item pool and functionality) and everything a race seed's ROM keeps from the tracker. Every reading of that seed then carries the file's settings where the ROM states none (`withSeedFile`: the ROM's known ones stand). Such a seed is held against the board only once its file has settled (`awaitsFile`), whatever it said, so the board never switches twice; by then the first reading is on the board, which counts as fresh if it holds the game alone (`Follower.holdsGameOnly`). A seed of another generator is held against the board at its first reading. Across the tracker's tabs one session too: the tab that runs it holds the Web Lock `alltp-tracker-autotrack`, another waits (`elsewhere`) and takes over when it is let go. The session's readings are laid on the run by `apps/web/src/autotrack/follow.ts` (see History).

- **`Progress`** — the run; "New game" (`reset`, which keeps the run type and its settings), `applyPreset`, `applyRun` and `loadProgress` replace it. `applyRun(presetId, settings, lay?)` starts a run of a run type under any settings, with what `lay` sets on the fresh run (the game, for a switch to the seed's: `Follower.switchRun`), as one undo step; `applyPreset` is `applyRun` with the preset's own settings. `updateSettings(change)` changes the settings that move no dungeon counter (`TunableSetting`: crystals, item placement, pool, functionality, accessibility) in the run going, its progress kept, as one undo step (none when nothing changes).
  - `items` — keyed by item id; `boolean` (toggles) or `number` (progressive). `handleItemClick` steps `-1` for `chest*` counters and `+1` for everything else, wrapping within `itemRange(item, settings)`: a dungeon counter counts its items left from `counterMax` (and the dungeon items that leave the dungeon, every location in Full Shuffle), the rest from `itemsMin` to `itemsMax`. `bossN` (1 alive, 2 beaten) is the only "boss beaten" flag: the grid cell and the map marker both read and toggle it. `bigkeyN`, `mapN` and `compassN` (0 or 1) are a dungeon's own items; the grid shows the map and compass while they leave their dungeons (MC Shuffle and up), where the boss wants them.
  - `checked` — the locations checked on the map, by the pack's ids (`{ "kings-tomb": true }`); `toggleChecks` checks a marker's locations together, or none once all are. A dungeon's own locations are counted by its counter instead; autotracking checks them as well outside Race Mode, and derives the counter from them.
  - `smallKeys` — 10 entries, each capped by its dungeon's small keys in the pack (`SMALL_KEYS_MAX` in `logic/settings.ts`: Eastern Palace has none, so no toggle); `medallions` — 10 entries, only 8 and 9 used.
  - `presetId` / `settings` — run type from `apps/web/src/data/presets.ts`. Logic reads `settings` (e.g. `settings.dungeonItems`, read through `wildItems`), never a display preference.
- **`Prefs`** — how this device shows and drives the tracker (`mapLayout`: `auto` by default, `side-by-side` or `stacked`; `mapView`: the map panel's tab, `map` by default or `checks`; `bigKeysVisible`; `shortcuts`). A pref added with a default needs no save version: `restorePrefs` fills it in. They survive a new game, a preset switch and an import, and stay out of save files and the undo history. `applyRun` changes `bigKeysVisible` only when the run's maps and compasses start or stop leaving their dungeons.
  - `shortcuts` — `{ enabled, keymap }`, one self-contained object so a later save format or the desktop app can carry it as is. The model lives in `apps/web/src/data/keymap.ts` (plain data, no DOM): `keymap` maps an action (`advance:hookshot`, `back:chest3`) to a chord (`Shift+KeyW`: modifiers, then a `KeyboardEvent.code`). `restoreShortcuts` validates a saved one.

## Saves

- **Persisted shape changes** bump `PERSIST_VERSION` and add a step to `migrate` in `persistence.ts`, which upgrades localStorage and imported files alike; then update `toPersisted`, `restoreProgress` / `restorePrefs` together. Never bump the version without a migration — persist would silently drop every existing save.
- `validateProgress` checks every field against the current tables. `parseSave` (import) refuses a file with any invalid field and names it; rehydration from localStorage is lenient and keeps the valid fields.
- Exports are `{ format: "alltp-tracker-save", game: "alttpr", version, progress }` (localStorage also keeps `game`); a file of another game is refused, and bare objects from earlier versions still import. Version 6 checked locations by the pack's ids: its migration expands each version 5 chest flag through the pack's `LEGACY_CHESTS` and carries a keysanity counter's items found. Version 7 takes the small-key maxima from the pack: its migration brings Eastern Palace's count, which could be 1, to 0. Versions 8 and 9 add run settings a seed sets (swordless and the crystal counts; then item placement, accessibility, item pool and functionality): their migrations give every earlier run the site's defaults the tracker assumed. Version 10 names the dungeon items as alttpr.com does (`dungeonItems`): its migration turns keysanity on into `full`, off into `standard`. An item id added to `items` needs no version: a save without it restores it at its fresh value, and an older version ignores it.

## History

`past` / `future` hold earlier `Progress` snapshots for undo/redo (cap 200), never persisted. Every action that changes `Progress` goes through `record(state, next)`, which pushes the current run and clears `future`; prefs bypass it. Rehydration (first load, another tab via `crossTabSync.ts`) clears the history.

What the game says is the one exception: `applyGameNews(change)` lays autotracking's news on the run as no step, and on every snapshot of `past` and `future` too, so undoing the player's change never undoes the game's. It sets nothing when `change` changes nothing, so a reading with no news writes neither the store nor localStorage. "Sync from game" (`syncWithGame`) is the player's action, one recorded step. The policy (a merge that never undoes the player's marks beyond the game, a sync that does, what Race Mode leaves alone) lives in `apps/web/src/autotrack/apply.ts`.

## Subscriptions

Components subscribe with selectors — `useGameStore((state) => state.items[item])` — never bare `useGameStore()`: a component re-renders only for the slice it shows. A selector must return a stable value; for several fields use one selector per field or `useShallow`.
