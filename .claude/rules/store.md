# State: a single Zustand store

ALttPR's modules live under `apps/web/src/games/alttpr/`: a short path below (`logic/…`, `stores/gameStore.ts`, `map/…`, `autotrack/follow.ts`) is relative to it, unless it names one of the shared modules (`components/ui/` Modal, Tabs, ConfirmDialog, ToolbarMenu, ToolbarIcons, UpdatePrompt, Header; `autotrack/guide.ts`, `autotrack/status.ts`; `hooks/` useGridNavigation, useNow, useToolbarFit, useTooltip; `stores/` tooltipStore, updateStore; `utils/`; `styles/`).

All game state lives in `apps/web/src/games/alttpr/stores/gameStore.ts`: `zustand` + `devtools` (development only) + `persist` (localStorage key `alltp-tracker-state`). The store holds only serializable data; the rules are the alltpr pack's, solved from it by a memoized selector (`apps/web/src/games/alttpr/logic/solution.ts`), never kept in a store. Its shape is `Progress & Prefs`, the run timer and the undo history, both types declared in `apps/web/src/games/alttpr/stores/persistence.ts`. Transient UI state lives in its own stores, never saved or undone: the tooltip (`tooltipStore.ts`), the run's analysis (`analysisStore.ts`: what every check and the go mode are missing, worked out for one solution and the tricks known when the browser is idle by `hooks/useRunAnalysis.ts`, and read only while that solution and those tricks are on screen), the keyboard layout map (what each key types, for labels) in `keyboardLayoutStore.ts`, a waiting new version (`updateStore.ts`, which also registers the service worker), voice commands (`voiceStore.ts`: the status, from opening the microphone to listening, why it failed, and the last command heard; only `enabled`, to listen on start, and `deviceId`, the microphone, are saved, under `alltp-tracker-voice`; one tab listens, holding the Web Lock `alltp-tracker-voice`, and a microphone refused is not asked again on start; the stream view never listens), the entrance picker (`entrancePickerStore.ts`: which entrance's destination is being noted, and the place the entrance pointed at leads to), and autotracking (`autotrackStore.ts`: the one session per page, loaded lazily on Connect, its status and last decoded reading; only `connectOnStart`, `keptSeed`, `raceChoice`, `raceSeen`, `darkRoomMap` and `darkRoomStyle` are saved, under `alltp-tracker-autotrack` (`raceSeen`: the seed was read as a race's, and Race Mode holds through a Disconnect and a reload, for the decoders too (the runtime's `raceHeld`, `isRaceModeOn` without the reading's own `race`: every reading is decoded as in a race, again at once when it changes) until the run is replaced (`runReplaced`, called by each game store's `reset` and `load`/`loadProgress`) or the player calls the race over, `endRace`; Undo back to a board of the replaced race sets it again, `boardRestored`; it is set by a flag that says race, unknown or unreadable, or a session ending with the flag unread; a tab on the release before this one rewrites the key without it, which the update notice ends; `autotrack/raceMode.ts`, no save version: `mergeRaceChoice` reads an absent one as false; ALttPR's and SMZ3's only, Super Metroid's save has none); the stream view never connects), and the dark room (`darkRoomStore.ts`: the room Link is in and where, decoded by the pack's `decodeDarkRoom` and handed over by the runtime's `darkRoom` sink, in two slices so the tiles are not drawn again as he walks; beside them, from the runtime's `darkRoomArt` sink, the room drawn in the game's graphics (`picture`, kept while its `version` holds), Link's sprite (`sprite`, kept while its pixels hold) and `art`, whether they are drawn or why not (`showArt`; `show(null)` clears them with the room); memory only, never saved, never in the reading, the run, an export, a shared link, live follow, the stream view or the overlay API, which a spec holds the modules that save, share, stream or follow to never import; cleared when the session stops, the option goes off, Race Mode comes on or the room is lit or has the Lamp or Link leaves the dungeon; kept as it is under a menu, a text box or a scroll, the pack's `darkRoomHeld`). `darkRoomMap` is the "Dark room map" option (a device pref, on by default, a save without it or with another type reads as on through `mergeSaved`, so no version): the session follows it at once (`Runtime.setDarkRoom`, `AutotrackSession.setOptIn`), and off, none of the dark room's ranges is read. `darkRoomStyle` (`"art"` by default, or `"plan"`; any other saved value reads as art through `mergeSaved`, so no version) is the map's style: the session reads the picture's ranges and the ROM's graphics only for art (`Runtime.setDarkRoomArt`, the `dark-room-art` switch, on only while the map is on too). `raceChoice` is Race Mode as the player sets it (`apps/web/src/autotrack/raceChoice.ts`, shared by every game's autotracking: for a game with a race flag `auto`, the flag, by default, or `on`, never `off`; Map Rando's `on` or `off`; a saved value the game does not offer reads as its default through `mergeRaceChoice`, so no version): it is handed to the session as it starts (`raceSetting`) and as it changes (`Runtime.setRaceMode`, which decodes the last reading again under it), from this tab or another, since each game's autotracking store follows the others through storage (`games/syncAcrossTabs.ts`). Each reading's seed is held against the board's run type before it is laid (`followSeed`, the words in `autotrack/seed.ts`): a Mystery run in the seed's world takes what it reveals at once (`checkSeed`'s `reveals`, laid with `revealSettings`, its words in the live region), what only the seed's file states staying hidden without one; a seed of another run type switches a fresh board (`isFreshRun`) at once, once per page and never for a seed the player kept (`keptSeed`), and leaves `news` for the live region, said with the status it came with and once more with the next; otherwise `useSeedCheck` (derived from the reading and the board, never stored) feeds SeedPrompt, whose `switchToSeed` and `keepRunType` the player answers. A seed whose name (the header's) is an alttpr.com hash asks alttpr.com for its file once per connection, outside Race Mode only (`seedFile`, transient: "loading", the settings or why none, from `autotrack/seedFile.ts`; a race reading lets it go): it states what no ROM does (item placement, accessibility, item pool and functionality, a Mystery seed). The file holds the seed's patch, every item placement with it, so Race Mode never asks for it: a race seed's run type stays the racer's, and a Mystery race is never switched to on its own. Every reading of that seed then carries the file's settings where the ROM states none (`withSeedFile`: the ROM's known ones stand). Such a seed is held against the board only once its file has settled (`awaitsFile`), whatever it said, so the board never switches twice; by then the first reading is on the board, which counts as fresh if it holds the game alone (`Follower.holdsGameOnly`). A seed of another generator is held against the board at its first reading. Across the tracker's tabs one session too, whatever their game: the tab that runs it holds the Web Lock `alltp-tracker-autotrack` (`apps/web/src/autotrack/lock.ts`, which every game's autotracking store takes), another waits (`elsewhere`) and takes over when it is let go. The session's readings are laid on the run by `apps/web/src/games/alttpr/autotrack/follow.ts` (see History).

- **`Progress`** — the run; "New game" (`reset`, which keeps the run type and its settings), `applyPreset`, `applyRun` and `loadProgress` replace it. `applyRun(presetId, settings, lay?)` starts a run of a run type under any settings, with what `lay` sets on the fresh run (the game, for a switch to the seed's: `Follower.switchRun`), as one undo step; `applyPreset` is `applyRun` with the preset's own settings. `updateSettings(change)` changes settings in the run going, its progress kept (`retune`), as one undo step (none when nothing changes): the `TunableSetting`s, those a Mystery run discovers (goal, swords, crystals, item placement, pool, functionality, accessibility) and its dungeon items, whose counters keep their items found (the old top less what is left, counted again from the new top), the key cells following as `applyRun` has them. A setting changed is no longer hidden. `hideSetting(setting)` hides one again (one undo step), and `revealSettings(change)` lays what a seed reveals on a Mystery run as the game's news: no step, on every snapshot of the history too.
  - `items` — keyed by item id; `boolean` (toggles) or `number` (progressive). `handleItemClick` steps `-1` for `chest*` counters and `+1` for everything else, wrapping within `itemRange(item, settings)`: a dungeon counter counts its items left from `counterMax` (and the dungeon items that leave the dungeon, every location in Full Shuffle), the rest from `itemsMin` to `itemsMax`. `bossN` (1 alive, 2 beaten) is the only "boss beaten" flag: the grid cell and the map marker both read and toggle it; Castle Tower's is `agahnim` and Ganon's Tower's `agahnim2` (0 or 1). The counters are `chestN` for the grid's ten and `chest12` for Ganon's Tower (`COUNTER_INDICES`). `bigkeyN`, `mapN` and `compassN` (0 or 1) are a dungeon's own items, by key dungeon index (the castles' as their pools hold them: `map10`, `bigkey12`, `map12`, `compass12`); the grid shows the map and compass while they leave their dungeons (MC Shuffle and up), where the boss wants them.
  - `checked` — the locations checked on the map, by the pack's ids (`{ "kings-tomb": true }`); `toggleChecks` checks a marker's locations together, or none once all are. A dungeon's own locations are counted by its counter instead; autotracking checks them as well, in Race Mode too (v2.0's dungeon-locations), and derives the counter from them.
  - `smallKeys` — 13 entries, one per key dungeon (`KEY_DUNGEONS` in `logic/settings.ts`: the grid's ten, then Hyrule Castle, Castle Tower, Ganon's Tower), each capped by its dungeon's small keys in the pack (`SMALL_KEYS_MAX`: Eastern Palace has none, so no toggle); `medallions` — 10 entries, only 8 and 9 used.
  - `timeline` — when each thing held was found (`apps/web/src/games/alttpr/logic/timeline.ts`): `item:<id>` for an item held or not, `item:<id>:<level>` for each level of a progressive one (a boss's 2 is beaten) or each bit of one whose bits are items (the bow's 1 is the silver arrows, its 2 the bow; the boomerangs'), `check:<location>`, each a `Stamp` `{ at, ms }` (the instant, and the run timer's reading then, `null` before it started). What an item records for the pack (`PACK_ITEMS`) says which: dungeon counters, picked prizes and the spacer are not finds. `record` stamps what a change finds (`stampTimeline`: a level gained or a location checked gets the stamp, one lost loses its entry), unless the change brings its own timeline (`reset`, `applyRun`: empty; `loadProgress`: the file's). Being part of `Progress`, it travels with undo and redo, which give back the very stamps, and with save files. A save without it (any before 2.20) restores none and dates nothing it held: no version needed. `validateProgress` refuses a stamp that is not one and drops a key this version does not know (`isTimelineKey`).
  - `entrances` — where each shuffled entrance leads, as noted: the pack's entrance id to its target's (`packs/alttpr/src/entrances.ts`). `noteEntrance(entrance, target | null)` and `noteEntrances(notes)` (a hole and its cave's door) are one undo step; a target leads from one entrance only, so noting it at one forgets it at another (`withNotes`, which autotracking's notes go through too: outside Race Mode, `follow.ts` notes each door or hole the game shows Link went through as the game's news, no step, once per change, loading the entrance tables only in a run whose entrances the assistant knows). `validateProgress` checks the ids' shape only, so the tables load with the assistant alone; an unknown id is shown as nothing. A save without it (any before 2.24) notes none: no version needed.
  - `seed` — the seed the run is played on: the hash alttpr.com names it by (the ROM header's `VT <hash>`), or null while unknown. It is `Progress.seed: string | null`, `isSeedId`-checked (`games/seedId.ts`, shared with the other games), so it travels with undo, exports and shared links; a save without it restores null: no version needed. Set by `follow.ts` through `recordSeed` (`games/seedId.ts`, shared by the three followers) from every reading of a game in play whose header names another seed than the run's (race seeds included: the title is on the screen), as the game's news: no step, and on the history's snapshots too but for those of another seed, so undoing New game gives the earlier run back with its own seed. It is also set by `applyRun`'s `lay` for a run started from a seed's hash (`PresetSelector` after `SeedImport`), and cleared by `reset`, `applyRun` and `applyPreset` (a fresh `createProgress`: null) and replaced by `loadProgress`. It is not part of `isFreshRun`. Nothing shows it yet.
  - `presetId` / `settings` — run type from `apps/web/src/games/alttpr/data/presets.ts`. `settings.glitches` is the glitched logic a seed was generated for (`Glitches`, alttpr.com's values; absent for None, the presets', so no save version; `isRunSettings` refuses `"none"` or any other value): the pack models none of them (`logicModelled`), so every check reads maybe; only a seed sets it (`checkSeed`, the seed's `logic` when known, the run's own otherwise), and a preset clears it. `settings.hidden` lists a Mystery run's settings not known yet (`HIDEABLE`): their values only stand in, `packSettings` passes them to the pack as `UNKNOWN` and the logic reads them as maybe. It is optional, absent once all are known: no save version; `isRunSettings` refuses a list of anything else, or one twice. A save of the Ambrosia placeholder reads as Mystery. The in-logic solution reads `settings` (e.g. `settings.dungeonItems`, read through `wildItems`), never a display preference. The one preference the logic's answers meet is `tricks`, through a selector of its own (`trickSolutionOf`) that `solutionOf` never reads: what the player sees is the in-logic solution plus that overlay, and the in-logic solution, the analysis and the go mode stay what the rules say.
- **`Prefs`** — how this device shows and drives the tracker (`mapLayout`: `auto` by default, `side-by-side` or `stacked`; `mapView`: the map panel's tab, `map` by default, `checks`, `entrances` (shown as the map in a run without shuffled entrances) or `run`; `bigKeysVisible`, set from the "Show key cells" checkbox of the Mode dialog; `autoTimer`: whether the game starts and stops the run timer, on by default; `timerClock`: `real` by default or `game`, the clock the timer shows; `shortcuts`; `tricks`). A pref added with a default needs no save version: `restorePrefs` fills it in. They survive a new game, a preset switch and an import, and stay out of save files and the undo history. `applyRun` changes `bigKeysVisible` only when the run's maps and compasses start or stop leaving their dungeons.
  - `tricks` — `{ enabled, techniques }` (`apps/web/src/games/alttpr/data/tricks.ts`): whether the map marks the checks a trick opens, off by default, and which of the pack's six `TrickId`s the player knows, all six once on. `restoreTricks` reads a saved one leniently (a switch that is not a boolean keeps the current one; the techniques keep the known ids, each once, in the pack's order), so it needs no save version; `setTricks` is a preference, no undo step. It stays out of exports, shared links and the history, like every pref, and `reset`, `applyRun` and an import keep it. `tricksShown` (`logic/solution.ts`) says whether it applies to the run: on, with a trick known, and not a `crossedLogic` run, which has no tricks world.
  - `shortcuts` — `{ enabled, keymap }`, one self-contained object so a later save format or the desktop app can carry it as is. The model lives in `apps/web/src/games/alttpr/data/keymap.ts` (plain data, no DOM): `keymap` maps an action (`advance:hookshot`, `back:chest3`) to a chord (`Shift+KeyW`: modifiers, then a `KeyboardEvent.code`). `restoreShortcuts` validates a saved one. The desktop app's global shortcuts are another `{ enabled, keymap }`, off by default, in their own store (`games/alttpr/desktop/globalShortcutsStore.ts`, `alltp-tracker-global-shortcuts`): device settings, neither saved with a run nor in an export, and no site bytes.

- **`timer`** — the run timer (`RunTimer` in `apps/web/src/utils/runTimer.ts`, shared with Archipelago's board, pure: `{ startedAt, elapsedMs, finished }`, running while `startedAt` holds the epoch instant it started; what it shows is worked out from the clock as it is drawn, so the store never ticks). It belongs to the run but stays out of `Progress`: `startTimer`, `pauseTimer`, `finishTimer` and `resetTimer` record no undo step, and undo never moves it. It is saved beside the run (`toPersisted`; `restoreTimer` reads anything else as an idle timer, so it needs no save version) and follows other tabs and the stream view through storage. `reset`, `loadProgress` and the player's `applyRun` / `applyPreset` set it back to idle; `Follower.switchRun` keeps it (`applyRun(…, keepTimer)`), since the switch to the seed's run type comes as play begins. While `autoTimer` is on, `follow.ts` asks `timerNews` (`logic/timer.ts`) of each reading: an idle timer starts when a reading in play follows one before it (`beforePlay`: the title, the file select, the spawn select), so connecting mid-run starts nothing; a running one finishes at the first reading of the goal. With `timerClock` at `game` (a pref, saved in the run's storage and the same for the stream view; no save version, `restorePrefs` fills in `real`), `follow.ts` asks `gameClockOf` (`logic/timer.ts`) instead and `alignTimer(clock, at)` sets the timer on it (`alignTimer` in `utils/runTimer.ts`, pure and shared by the other games' followers: given `{ ms, status: "running" | "paused" | "over" }` and the reading's instant it sets `elapsedMs` to the game's time and `startedAt` to that instant while running, null while not, finishes at the goal, leaves a finished timer be and returns the same object for a running timer within 250 ms of the game, so most readings write nothing). The clock is `romStats.playFrames` → `playTimeMs`: running when the game is not `beforePlay` and the counter moved since the reading before (the follower keeps the last `playFrames`; an unmoved counter reads paused, so the timer never ticks past the game and is set back). A paused emulator serves the same bytes, so no reading comes at all: the session's `onSteady` (`packages/autotrack`: a poll that read memory and found it unchanged, never the first poll nor while the page is hidden) reaches the follower's `steady(at)` through the runtime's sink (`GameRuntimeSink.steady`, optional), which sets the timer on the last clock as paused (`alignTimer`, no write if already so) while Game time follows it; the next changed reading resumes it. Only for a counter the pack reads on every tick, paused before play, over at the goal; never applied from a counter of 0 (the title and the file select clear it: a running timer is paused instead), nor in Race Mode or with the stats unsettled, which fall back to the real-time rules above. Game time ignores `autoTimer`; no undo step.

## Super Metroid's run (`games/sm/store.ts`)

Its own Zustand store (`useSmStore`), persisted under `alltp-tracker-sm` (version 1), apart from ALttPR's so each game keeps its run: the items held (`items`, a count by the pack's item id), the seed's objectives (`objectives`) and those done (`done`), the two settings that change the grid (`wallJump`, `splitSpeed`) and the seed it is played on (`seed`: Map Rando's name from `$DF:FEF0`, which the follower records with `recordSeed` from a reading in play, race or not; null while unknown; the schema defaults a save without it to null, so no version; `reset` clears it) and `found`, the item locations autotracking saw collected, `Partial<Record<LocationKey, Stamp>>` by the log's `room_id:node_id` (the pack's `LOCATION_KEYS`; `Stamp` is `games/stamp.ts`'s, shared with ALttPR's timeline: the instant and the run timer's reading, `ms` null before it started). It is part of the run (`progressOf`: history, export, shared link, live follow) and defaults to `{}` in a save without it, so no version; `reset`, New game and an import replace it. The follower lays it as the game's news (below), and only the review reads it. Beside the run, saved with it but never a step of the history nor part of an export or a shared link, the run timer, the slice shared with SMZ3's store (`games/timerSlice.ts`: the fields, the actions `startTimer`/`pauseTimer`/`finishTimer`/`setAutoTimer`/`setTimerClock`/`alignTimer`, how a save restores them): `timer` (`utils/runTimer.ts`, as ALttPR's), `autoTimer` (start and stop with the game, on by default), `timerClock` (`real` or `game`, real by default); and, Super Metroid's alone, `clockBase` (the RTA clock's frames when the timer was at 0, or null: the clock counts since the SRAM was set up, so the game's time is the frames since it); a save without them restores as idle, on, real and null, a damaged one the same, and `reset`, `load` and `resetTimer` clear the timer and the base. Its shape is a `zod/mini` schema, the type derived from it: a saved run that does not parse, or holds a count beyond its pool, is dropped for a fresh one (another tab's, ignored), an export writes the run's fields only (`progressOf`, never the undo history beside them), and an import (`parseSave`) says why it refuses a file (not JSON, not a save, another game's, a newer version, a run that is not one, a count beyond the pool). Helpers the store's `merge` calls are declared before the store: it restores a saved run as it is created. `step` wraps within 0 and the item's pool; `reset` keeps the seed's objectives and settings; undo and redo hold 200 steps; `applyGameNews` lays what the game says on the run and its history as no step. The history's actions (`record`, `undo`, `redo`, `applyGameNews`) are `games/runHistory.ts`'s `historyActions`, and the save file (`exportSave`, `parseSave`, `IMPORT_ERRORS`) is `games/saveFormat.ts`'s `createSaveFormat`, both shared with SMZ3's store, which give each its own `get`/`set` and schema. `games/sm/module.ts` follows other tabs through `games/syncAcrossTabs.ts`, for the stream view.

Its autotracking lives in `games/sm/autotrack/`, as ALttPR's: `store.ts` (`smAutotrack`, a game session from `apps/web/src/autotrack/gameSession.ts`'s `createGameAutotrack`: the one session per page, loaded lazily on Connect from `runtime.ts` with the pack's `MAP_RANDO_AUTOTRACK`, its status and last reading, `reading.ts`'s decode; only `connectOnStart` and `raceChoice` (Map Rando has no race flag: `createGameAutotrack`'s `raceFlag: false` offers `on`, the default, and `off` (`RACE_CHOICES.flagless`); no save version: `mergeRaceChoice` reads any value the game does not offer as its default, so a legacy "auto", which every save held as the default it then was, reads as `on`, and an older tab reads "off" as Auto, off for this game. Its race profile permits the items, the boss flags (`boss-flags`, `$7E:D828-$7E:D82F`) and the header and game state they need, and forbids the seed's objectives and settings (`objective-count`, `objective-flags`, `seed`), the event flags (`events`, `$7E:D820-$7E:D827`), `game-time` (the RTA clock; the equipment is read word by word, `items-collected`, `beams-collected` and the five `max-*`, so no HUD nor in-game time) and `locations` (the collected bits and the Nothing mask); `runtime.ts` decodes each reading under Race Mode (`readSm(…, race)`, which then leaves the seed, objectives, locations, clock and goal unread whatever a snapshot still holds) and again when it changes, and a race reading's `bossKills` (`decodeBossKills`) are laid done among the objectives the player set) are saved, under `alltp-tracker-sm-autotrack`; the stream view never connects) and `follow.ts` (`createSmFollower`, per session: only while a game is in play, it lays each reading's news through `applyGameNews`: an item's count when the game's changes, or the player's if higher; the ROM's objectives, those it says done added to the player's; the Wall Jump Boots and split Speed Booster as the seed sets them; each location newly seen collected, added to `found` with the stamp of that reading (`stampOf` on the timer once the reading has followed it), never taken back nor re-dated, which `applyGameNews` also lays on the history's snapshots). The bits come from `decodeCollected`, which applies the ROM's Nothing mask (`bits & ~mask`) so `found` never names a Nothing location, and their category `locations` is forbidden in a race: Race Mode reads neither range, and `found` stays as it was. The follower also drives the run timer outside Race Mode (in it the timer is the player's: no Map Rando race rule speaks of it), whether or not a game is in play (`games/gameTimer.ts`'s `timerNews` and `gameClockOf`, shared with SMZ3's follower, and `autotrack/timer.ts`'s `clockBaseOf` are the pure steps): with `autoTimer`, it starts an idle timer at the first reading in play after one before play (`beforePlay`: states `$00-$06` and `$1F`; a pause, a door or a death is no start, nor is a first reading with none before) and notes the clock's frames as `clockBase`, and finishes a running one at the goal (the escape event with state `$26` or `$27`); with `timerClock` `game`, outside Race Mode, a timer that has begun is set on the RTA clock at each reading (`alignTimer`, as ALttPR's), paused while the counter stands still, finished at the goal when `autoTimer` is on, its base taken again from the timer's own time when it is unknown or the clock fell behind it; a reading the clock's flush split (`clockStraddled`) is held. Race Mode never reads the clock, nor the escape event, so it is then the real-time timer, started and stopped by the player. A steady poll (`steady(at)`, as ALttPR's) holds a timer set on the clock at its last time while the emulator is paused. No seed check: a Map Rando ROM states its own objectives and settings.

## SMZ3's run (`games/smz3/store.ts`)

Its own Zustand store (`useSmz3Store`), persisted under `alltp-tracker-smz3` (version 1): the items held (`items`, a count by the smz3 pack's item id, keys and keycards and rewards included), the locations checked (`checked`, the pack's ids), what the player knows of Misery Mire's and Turtle Rock's medallions (`pads`, `unknown` until set) the run's settings (`settings`: Super Metroid's logic, keysanity, the three thresholds) and the seed it is played on (`seed`: the guid from `$80:FF60`, read outside Race Mode only and recorded by the follower with `recordSeed`; null while unknown and in races; defaulted to null in a save without it, so no version; `reset` clears it). Its shape is a `zod/mini` schema, the type derived from it; a saved run that does not parse or holds a count beyond its pool is dropped, one from an older pool completed at 0, and `parseSave` says why it refuses a file, as Super Metroid's. Every change, settings and pads included, is one undo step (200 kept); `reset` keeps the settings and forgets the pads. Beside the run, saved with it but never a step of the history nor part of an export or a shared link, the run timer, the same slice as Super Metroid's (`timer`, `autoTimer`, `timerClock`; no base: the games' counters count from the file's start); `reset`, `load` and `resetTimer` clear the timer, a save without it restores as idle, on and real. `games/smz3/logic.ts` reads the run: `solutionOf` compiles the pack's world once per settings and solves once per items, pads and settings (without keysanity the state holds every keycard, as upstream's logic does), and `markerState` is what a marker shows. `games/smz3/module.ts` follows other tabs through `games/syncAcrossTabs.ts`, for the stream view; its history and save file are the same `historyActions` and `createSaveFormat`.

Its autotracking lives in `games/smz3/autotrack/`, as Super Metroid's: `store.ts` (`smz3Autotrack`, a game session saved under `alltp-tracker-smz3-autotrack`), `runtime.ts` (the pack's `SMZ3_AUTOTRACK`; Race Mode on until the seed's race bit says otherwise, or always on as the player sets it, every reading decoded again when it changes), `reading.ts` (both games' items, but in Race Mode no crystal, red or blue (`decodeItems(…, race)`: v2.0 forbids telling a 5/6 crystal), so both cells stay the player's, the locations checked, the seed and, outside Race Mode, its guid (`guid`, `race-mode` in a race), its requirements and the game time: `beforePlay`, `goal` (the credits byte) and `clock`, the two games' frame counters added, `race-mode` in a race) and `follow.ts` (`createSmz3Follower`, per session: only while the running game is in play, it lays each reading's news through `applyGameNews`, which rebases the history as Super Metroid's does: an item's count when the game's changes, or the player's if higher; the locations the game says checked, added; the seed's guid outside races, as the run's `seed`; the seed's logic and keysanity and, outside races, its thresholds and medallions). The follower also drives the run timer, whether or not a game is in play: with `autoTimer`, it starts an idle timer at the first reading in play after a reading before play (`armed`: set by one before play, cleared by one in play, so the readings between, a portal or a load, keep it and a file that starts in either game starts the timer; a pause, a door, a death or a first reading with none before start nothing) and finishes a running one when the credits run (the game byte's low byte `$11`); with `timerClock` `game`, outside Race Mode, a timer that has begun is set on the sum of the counters at each reading (`alignTimer`, as ALttPR's and Super Metroid's), paused while the sum stands still, finished at the credits on their total (a tick that sees the credits has not read the counters yet, a new mode: the timer waits for the next one rather than finish on real time). The sum is the game's, so a death or a reload, which sets both counters back to the last save, sets the timer back with them (`alignTimer` follows a clock that falls behind), as the credits' own total would; nothing keeps it monotonic. A steady poll (`steady(at)`, wired in `runtime.ts` by `session.onSteady`) holds a timer set on the counters at its last time while the emulator is paused. Race Mode never reads the counters, so the timer is then real time, still started and stopped by the game's state.

## Archipelago's run (`games/archipelago/store.ts`)

Its own Zustand store (`useArchipelagoStore`), persisted under `alltp-tracker-archipelago` (version 2): the slot as the room's server last stated it, never a mark of the player's. `room` (seed name, generator version, team, slot, slot name, game, the game's name-data checksum), `items` (`{ name, count, flags }`: AP's names resolved, one entry per name in the order its first copy came, AP's flags OR-ed), `checked` and `missing` (the slot's location ids), `sent` (what each checked location held and for which slot), `players` (with each one's client status), `hints` (resolved, `forMe` and a status name), `hintPoints`, `hintCost`, `slotData` (plain values, outside races only), `feed` (the room's last 100 lines, resolved into parts), `raceMode`, `received` (the server's next item index), `updatedAt`; and what the player sets, which `apply` keeps: `timer` (the shared `RunTimer`; `startTimer`, `pauseTimer`, `resetTimer`, `countdownEnded`, the room's countdown at 0 starting an idle timer, and `goalReached`, the slot's own client status reaching 30 stopping a running one for good, both while `prefs.countdownTimer` holds) and `prefs` (`hideChecked`, `feedScope` "mine" or "room", `announce`, `countdownTimer`, `side` the tab beside the items; `setPref`, which writes nothing when nothing changes). Its shape is a `zod/mini` schema; a saved run that does not parse is dropped for an empty board. Version 1 runs go through `migrateRun` first (the new fields empty, the timer idle, the prefs defaulted, `hideChecked` kept, every status null): a version bump without its step would drop every saved run. No history, no undo, no save format: `importRun` refuses. It is what live follow, the stream view and the overlay read, so it never holds the address, the port or the password.

Only `runtime.ts` writes the server's part, through `connection.ts`'s sink: the session's snapshot and this connection's feed lines are projected (`project.ts`, pure; the lines written out after the board's saved feed) at most once every 250 ms (`trailing`), and not at all between connections, before Connected, when nothing changed, or when the same run's item list is shorter than the board's (the moment before the server resends it). Another run (seed, generator, team, slot or game) replaces the board with a notice (`notice`, transient). What the slot received while the board was away is the connection store's `away` (transient, until dismissed).

The connection (`games/archipelago/connection.ts`, `useApConnectionStore`) keeps its own key, `alltp-tracker-archipelago-connection`, device-only and never published: the Room field, the room link, the slot, `connectOnStart`, `rememberPassword`, this device's uuid in the room (its `zod/mini` schema drops a saved value that does not hold); and, transient, `active`, the session's `status` and `since`, `unavailable` (the session's chunk failed to load), the notice, `away` and `prefill` (a join link's room and slot, `joinLink.ts`, until the dialog takes them; nothing connects from it) The password is `alltp-tracker-archipelago-password` in sessionStorage, and in localStorage only while remembered (`savePassword` removes it there at once when not). One session per page (`connect`, `stop`, `disconnect`, `retry`), its code a chunk loaded on Connect; across the browser's tabs one connection, holding the Web Lock `alltp-tracker-archipelago` (`createTabLock`); `followOtherTabs` follows the settings through storage and stops or moves a session another tab disconnected or pointed elsewhere. The names and location groups the checks need are `useApNamesStore` (`names.ts`, transient), from the server in the connected tab and from the IndexedDB cache (`datapackageCache.ts`) in the others. `docs/archipelago.md` is the design doc.

## The review (`review/store.ts`)

`useReviewStore` holds the spoiler log open for the run (`review: Loaded | null`, `open`, `close`): the parsed log, how it was bound (`verified` or `not-verified`), the file's name and the run's seed when it opened. It is **memory only**: no `persist`, never in `localStorage`, an export, a shared link, the stream view, the overlay API or live follow (they read the game's own store; a spec holds the modules that save, share, stream or follow a run to never import it). A game shows a review only while its gate stands open and the run's `seed` is still `boundSeed` (`review/active.ts`, over each game's gate and seed in `games/alttpr/review/useReview.ts`, `games/sm/review/useReview.ts` and `games/smz3/review/useReview.ts`), and `useCloseReview` drops it the moment that stops: Reset timer, New game, an import or shared run (all put the timer back to idle), a seed switch, Race Mode on. The timer's `finished` is what makes a run over: autotracking at the goal, or the player's End run, which calls `finishTimer` (no undo step, as ever).

## Saves

- **Persisted shape changes** bump `PERSIST_VERSION` and add a step to `migrate` in `persistence.ts`, which upgrades localStorage and imported files alike; then update `toPersisted`, `restoreProgress` / `restorePrefs` together. Never bump the version without a migration — persist would silently drop every existing save.
- `validateProgress` checks every field against the current tables. `parseSave` (import) refuses a file with any invalid field and names it; rehydration from localStorage is lenient and keeps the valid fields.
- **Shared links** (`apps/web/src/share/`, `docs/share.md`): Share encodes what Export writes into the address's fragment, `#run=` plus base64url of the deflated, minified JSON. The page's `SharedRunPrompt` (among the notices of each game's app, never in the stream view) decodes it under two bounds (64 K characters of payload, 1 MiB inflated), reads the game from the envelope with Zod, then hands the text to that game's `importRun`, which is `parseSave` (the same validation and migrations as Import) and `load`/`loadProgress` (the same single undo step). Nothing is applied before Open; a link that does not decode or validate changes nothing. Another game's run is laid in its own store, then `switchGame` loads the page again (the undo point does not survive the reload). The run's `seed` is a plain string in every link, packed or not (not a codec field: `docs/share.md`). ALttPR and SMZ3 write a packed link (format `alltp-tracker-link`, `games/<id>/share.ts` over `share/packed.ts`): `checked` as a bitset over the pack's ordered locations, ALttPR's `items` and `timeline` as varints and bits, with the sizes of those ordered tables and a digest of their contents in the link: the tables are append-only (a new item goes at the end of ALttPR's `SHARE_ITEMS`, a new location at the end of the pack's), a link made against a prefix of today's still opens, and one made against tables reordered or cut is refused ("another version of the tracker"). The game's `importRun` expands it into a plain save first; a plain link (the first version's, and Super Metroid's) opens untouched. A save format change needs no link version: the packed fields are expanded back to a save, which `migrate` already reads. A change of a packed field's bytes does: the link's `link` is its layout version, every codec reads 2 (`LINK_VERSION`), and one whose bytes changed writes the next (`PackCodec.version`) and keeps a reader for each version before, held to links its old writer recorded (`share/fixtures/`, never hand-written). ALttPR writes 3, its timeline in bits throughout, each drift as a change (`compactField`), but 2 for a save without a find, whose bytes are the same (`PackCodec.versionFor`: the earliest version whose bytes are the latest's, so older trackers keep opening it); SMZ3 writes 2. A link of a later version, or with a table longer than this tracker's, is a newer tracker's: refused with `NEWER_VERSION` and `newer`, which the notice answers with Reload, the fragment kept. A table that changes order breaks the links made before it (the digest refuses them), so never reorder one; a new packed field must be added to the codec. ALttPR's link falls back to `withoutTimeline` when the full one passes 2000 characters (a run on the game's clock past about 280 finds: `docs/share.md`, "Length"); `makeLink` keeps the full one as `Link.full`, which the Share dialog offers to copy. The store never drops the timeline for it: a run opened from such a link has none, and its review says so (`no-timeline`).
- Exports are `{ format: "alltp-tracker-save", game: "alttpr", version, progress }` (localStorage also keeps `game`); a file of another game is refused, and bare objects from earlier versions still import. Version 6 checked locations by the pack's ids: its migration expands each version 5 chest flag through the pack's `LEGACY_CHESTS` and carries a keysanity counter's items found. Version 7 takes the small-key maxima from the pack: its migration brings Eastern Palace's count, which could be 1, to 0. Versions 8 and 9 add run settings a seed sets (swordless and the crystal counts; then item placement, accessibility, item pool and functionality): their migrations give every earlier run the site's defaults the tracker assumed. Version 10 names the dungeon items as alttpr.com does (`dungeonItems`): its migration turns keysanity on into `full`, off into `standard`. Version 11 counts the castle dungeons' small keys too: its migration adds their three counts, none found. Version 12 gives a keymap saved before the Half Magic cell its Slash and Shift+Slash keys, never moving a chord already held (`migrateV11`, the step to version 12). An item id added to `items` needs no version: a save without it restores it at its fresh value, and an older version ignores it.

## History

`past` / `future` hold earlier `Progress` snapshots for undo/redo (cap 200), never persisted. Every action that changes `Progress` goes through `record(state, next)`, which pushes the current run and clears `future`; prefs bypass it. Rehydration (first load, another tab via `games/syncAcrossTabs.ts`, which every game's module starts, filtered on `localStorage` and the store's key) clears the history.

What the game says is the one exception: `applyGameNews(change)` lays autotracking's news on the run as no step, and on every snapshot of `past` and `future` too, each stamped on its timeline with the same instant, so undoing the player's change never undoes the game's. It sets nothing when `change` changes nothing, so a reading with no news writes neither the store nor localStorage. "Sync from game" (`syncWithGame`) is the player's action, one recorded step. The policy (a merge that never undoes the player's marks beyond the game, a sync that does, what Race Mode leaves alone) lives in `apps/web/src/games/alttpr/autotrack/apply.ts`.

## Subscriptions

Components subscribe with selectors — `useGameStore((state) => state.items[item])` — never bare `useGameStore()`: a component re-renders only for the slice it shows. A selector must return a stable value; for several fields use one selector per field or `useShallow`.
