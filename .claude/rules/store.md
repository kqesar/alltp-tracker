# State: a single Zustand store

ALttPR's modules live under `apps/web/src/games/alttpr/`: a short path below (`logic/…`, `stores/gameStore.ts`, `map/…`, `autotrack/follow.ts`) is relative to it, unless it names one of the shared modules (`components/ui/` Modal, Tabs, ConfirmDialog, ToolbarMenu, ToolbarIcons, UpdatePrompt, Header; `autotrack/guide.ts`, `autotrack/status.ts`; `hooks/` useGridNavigation, useNow, useToolbarFit, useTooltip; `stores/` tooltipStore, updateStore; `utils/`; `styles/`).

All game state lives in `apps/web/src/games/alttpr/stores/gameStore.ts`: `zustand` + `devtools` (development only) + `persist` (localStorage key `alltp-tracker-state`). The store holds only serializable data; the rules are the alltpr pack's, solved from it by a memoized selector (`apps/web/src/games/alttpr/logic/solution.ts`), never kept in a store. Its shape is `Progress & Prefs`, the run timer and the undo history, both types declared in `apps/web/src/games/alttpr/stores/persistence.ts`. Transient UI state lives in its own stores, never saved or undone: the tooltip (`tooltipStore.ts`), the run's analysis (`analysisStore.ts`: what every check and the go mode are missing, worked out for one solution when the browser is idle by `hooks/useRunAnalysis.ts`, and read only while that solution is on screen), the keyboard layout map (what each key types, for labels) in `keyboardLayoutStore.ts`, a waiting new version (`updateStore.ts`, which also registers the service worker), voice commands (`voiceStore.ts`: the status, from opening the microphone to listening, why it failed, and the last command heard; only `enabled`, to listen on start, and `deviceId`, the microphone, are saved, under `alltp-tracker-voice`; one tab listens, holding the Web Lock `alltp-tracker-voice`, and a microphone refused is not asked again on start; the stream view never listens), the entrance picker (`entrancePickerStore.ts`: which entrance's destination is being noted, and the place the entrance pointed at leads to), and autotracking (`autotrackStore.ts`: the one session per page, loaded lazily on Connect, its status and last decoded reading; only `connectOnStart` and `keptSeed` are saved, under `alltp-tracker-autotrack`; the stream view never connects). Each reading's seed is held against the board's run type before it is laid (`followSeed`, the words in `autotrack/seed.ts`): a Mystery run in the seed's world takes what it reveals at once (`checkSeed`'s `reveals`, laid with `revealSettings`, its words in the live region), what only the seed's file states staying hidden without one; a seed of another run type switches a fresh board (`isFreshRun`) at once, once per page and never for a seed the player kept (`keptSeed`), and leaves `news` for the live region, said with the status it came with and once more with the next; otherwise `useSeedCheck` (derived from the reading and the board, never stored) feeds SeedPrompt, whose `switchToSeed` and `keepRunType` the player answers. A seed whose name (the header's) is an alttpr.com hash asks alttpr.com for its file once per connection (`seedFile`, transient: "loading", the settings or why none, from `autotrack/seedFile.ts`): it states what no ROM does (item placement, accessibility, item pool and functionality) and everything a race seed's ROM keeps from the tracker. Every reading of that seed then carries the file's settings where the ROM states none (`withSeedFile`: the ROM's known ones stand). Such a seed is held against the board only once its file has settled (`awaitsFile`), whatever it said, so the board never switches twice; by then the first reading is on the board, which counts as fresh if it holds the game alone (`Follower.holdsGameOnly`). A seed of another generator is held against the board at its first reading. Across the tracker's tabs one session too, whatever their game: the tab that runs it holds the Web Lock `alltp-tracker-autotrack` (`apps/web/src/autotrack/lock.ts`, which every game's autotracking store takes), another waits (`elsewhere`) and takes over when it is let go. The session's readings are laid on the run by `apps/web/src/games/alttpr/autotrack/follow.ts` (see History).

- **`Progress`** — the run; "New game" (`reset`, which keeps the run type and its settings), `applyPreset`, `applyRun` and `loadProgress` replace it. `applyRun(presetId, settings, lay?)` starts a run of a run type under any settings, with what `lay` sets on the fresh run (the game, for a switch to the seed's: `Follower.switchRun`), as one undo step; `applyPreset` is `applyRun` with the preset's own settings. `updateSettings(change)` changes settings in the run going, its progress kept (`retune`), as one undo step (none when nothing changes): the `TunableSetting`s, those a Mystery run discovers (goal, swords, crystals, item placement, pool, functionality, accessibility) and its dungeon items, whose counters keep their items found (the old top less what is left, counted again from the new top), the key cells following as `applyRun` has them. A setting changed is no longer hidden. `hideSetting(setting)` hides one again (one undo step), and `revealSettings(change)` lays what a seed reveals on a Mystery run as the game's news: no step, on every snapshot of the history too.
  - `items` — keyed by item id; `boolean` (toggles) or `number` (progressive). `handleItemClick` steps `-1` for `chest*` counters and `+1` for everything else, wrapping within `itemRange(item, settings)`: a dungeon counter counts its items left from `counterMax` (and the dungeon items that leave the dungeon, every location in Full Shuffle), the rest from `itemsMin` to `itemsMax`. `bossN` (1 alive, 2 beaten) is the only "boss beaten" flag: the grid cell and the map marker both read and toggle it; Castle Tower's is `agahnim` and Ganon's Tower's `agahnim2` (0 or 1). The counters are `chestN` for the grid's ten and `chest12` for Ganon's Tower (`COUNTER_INDICES`). `bigkeyN`, `mapN` and `compassN` (0 or 1) are a dungeon's own items, by key dungeon index (the castles' as their pools hold them: `map10`, `bigkey12`, `map12`, `compass12`); the grid shows the map and compass while they leave their dungeons (MC Shuffle and up), where the boss wants them.
  - `checked` — the locations checked on the map, by the pack's ids (`{ "kings-tomb": true }`); `toggleChecks` checks a marker's locations together, or none once all are. A dungeon's own locations are counted by its counter instead; autotracking checks them as well outside Race Mode, and derives the counter from them.
  - `smallKeys` — 13 entries, one per key dungeon (`KEY_DUNGEONS` in `logic/settings.ts`: the grid's ten, then Hyrule Castle, Castle Tower, Ganon's Tower), each capped by its dungeon's small keys in the pack (`SMALL_KEYS_MAX`: Eastern Palace has none, so no toggle); `medallions` — 10 entries, only 8 and 9 used.
  - `timeline` — when each thing held was found (`apps/web/src/games/alttpr/logic/timeline.ts`): `item:<id>` for an item held or not, `item:<id>:<level>` for each level of a progressive one (a boss's 2 is beaten) or each bit of one whose bits are items (the bow's 1 is the silver arrows, its 2 the bow; the boomerangs'), `check:<location>`, each a `Stamp` `{ at, ms }` (the instant, and the run timer's reading then, `null` before it started). What an item records for the pack (`PACK_ITEMS`) says which: dungeon counters, picked prizes and the spacer are not finds. `record` stamps what a change finds (`stampTimeline`: a level gained or a location checked gets the stamp, one lost loses its entry), unless the change brings its own timeline (`reset`, `applyRun`: empty; `loadProgress`: the file's). Being part of `Progress`, it travels with undo and redo, which give back the very stamps, and with save files. A save without it (any before 2.20) restores none and dates nothing it held: no version needed. `validateProgress` refuses a stamp that is not one and drops a key this version does not know (`isTimelineKey`).
  - `entrances` — where each shuffled entrance leads, as noted: the pack's entrance id to its target's (`packs/alttpr/src/entrances.ts`). `noteEntrance(entrance, target | null)` and `noteEntrances(notes)` (a hole and its cave's door) are one undo step; a target leads from one entrance only, so noting it at one forgets it at another (`withNotes`, which autotracking's notes go through too: outside Race Mode, `follow.ts` notes each door or hole the game shows Link went through as the game's news, no step, once per change, loading the entrance tables only in a run whose entrances the assistant knows). `validateProgress` checks the ids' shape only, so the tables load with the assistant alone; an unknown id is shown as nothing. A save without it (any before 2.24) notes none: no version needed.
  - `presetId` / `settings` — run type from `apps/web/src/games/alttpr/data/presets.ts`. `settings.hidden` lists a Mystery run's settings not known yet (`HIDEABLE`): their values only stand in, `packSettings` passes them to the pack as `UNKNOWN` and the logic reads them as maybe. It is optional, absent once all are known: no save version; `isRunSettings` refuses a list of anything else, or one twice. A save of the Ambrosia placeholder reads as Mystery. Logic reads `settings` (e.g. `settings.dungeonItems`, read through `wildItems`), never a display preference.
- **`Prefs`** — how this device shows and drives the tracker (`mapLayout`: `auto` by default, `side-by-side` or `stacked`; `mapView`: the map panel's tab, `map` by default, `checks`, `entrances` (shown as the map in a run without shuffled entrances) or `run`; `bigKeysVisible`; `autoTimer`: whether the game starts and stops the run timer, on by default; `shortcuts`). A pref added with a default needs no save version: `restorePrefs` fills it in. They survive a new game, a preset switch and an import, and stay out of save files and the undo history. `applyRun` changes `bigKeysVisible` only when the run's maps and compasses start or stop leaving their dungeons.
  - `shortcuts` — `{ enabled, keymap }`, one self-contained object so a later save format or the desktop app can carry it as is. The model lives in `apps/web/src/games/alttpr/data/keymap.ts` (plain data, no DOM): `keymap` maps an action (`advance:hookshot`, `back:chest3`) to a chord (`Shift+KeyW`: modifiers, then a `KeyboardEvent.code`). `restoreShortcuts` validates a saved one. The desktop app's global shortcuts are another `{ enabled, keymap }`, off by default, in their own store (`games/alttpr/desktop/globalShortcutsStore.ts`, `alltp-tracker-global-shortcuts`): device settings, neither saved with a run nor in an export, and no site bytes.

- **`timer`** — the run timer (`RunTimer` in `apps/web/src/games/alttpr/logic/timer.ts`, pure: `{ startedAt, elapsedMs, finished }`, running while `startedAt` holds the epoch instant it started; what it shows is worked out from the clock as it is drawn, so the store never ticks). It belongs to the run but stays out of `Progress`: `startTimer`, `pauseTimer`, `finishTimer` and `resetTimer` record no undo step, and undo never moves it. It is saved beside the run (`toPersisted`; `restoreTimer` reads anything else as an idle timer, so it needs no save version) and follows other tabs and the stream view through storage. `reset`, `loadProgress` and the player's `applyRun` / `applyPreset` set it back to idle; `Follower.switchRun` keeps it (`applyRun(…, keepTimer)`), since the switch to the seed's run type comes as play begins. While `autoTimer` is on, `follow.ts` asks `timerNews` of each reading: an idle timer starts when a reading in play follows one before it (`beforePlay`: the title, the file select, the spawn select), so connecting mid-run starts nothing; a running one finishes at the first reading of the goal.

## Super Metroid's run (`games/sm/store.ts`)

Its own Zustand store (`useSmStore`), persisted under `alltp-tracker-sm` (version 1), apart from ALttPR's so each game keeps its run: the items held (`items`, a count by the pack's item id), the seed's objectives (`objectives`) and those done (`done`), and the two settings that change the grid (`wallJump`, `splitSpeed`). Its shape is a `zod/mini` schema, the type derived from it: a saved run that does not parse, or holds a count beyond its pool, is dropped for a fresh one (another tab's, ignored), an export writes the run's fields only (`progressOf`, never the undo history beside them), and an import (`parseSave`) says why it refuses a file (not JSON, not a save, another game's, a newer version, a run that is not one, a count beyond the pool). Helpers the store's `merge` calls are declared before the store: it restores a saved run as it is created. `step` wraps within 0 and the item's pool; `reset` keeps the seed's objectives and settings; undo and redo hold 200 steps; `applyGameNews` lays what the game says on the run and its history as no step. The history's actions (`record`, `undo`, `redo`, `applyGameNews`) are `games/runHistory.ts`'s `historyActions`, and the save file (`exportSave`, `parseSave`, `IMPORT_ERRORS`) is `games/saveFormat.ts`'s `createSaveFormat`, both shared with SMZ3's store, which give each its own `get`/`set` and schema. `games/sm/module.ts` follows other tabs through `games/syncAcrossTabs.ts`, for the stream view.

Its autotracking lives in `games/sm/autotrack/`, as ALttPR's: `store.ts` (`smAutotrack`, a game session from `apps/web/src/autotrack/gameSession.ts`'s `createGameAutotrack`: the one session per page, loaded lazily on Connect from `runtime.ts` with the pack's `MAP_RANDO_AUTOTRACK`, its status and last reading, `reading.ts`'s decode; only `connectOnStart` is saved, under `alltp-tracker-sm-autotrack`; the stream view never connects) and `follow.ts` (`createSmFollower`, per session: only while a game is in play, it lays each reading's news through `applyGameNews`: an item's count when the game's changes, or the player's if higher; the ROM's objectives, those it says done added to the player's; the Wall Jump Boots and split Speed Booster as the seed sets them). No seed check: a Map Rando ROM states its own objectives and settings.

## SMZ3's run (`games/smz3/store.ts`)

Its own Zustand store (`useSmz3Store`), persisted under `alltp-tracker-smz3` (version 1): the items held (`items`, a count by the smz3 pack's item id, keys and keycards and rewards included), the locations checked (`checked`, the pack's ids), what the player knows of Misery Mire's and Turtle Rock's medallions (`pads`, `unknown` until set) and the run's settings (`settings`: Super Metroid's logic, keysanity, the three thresholds). Its shape is a `zod/mini` schema, the type derived from it; a saved run that does not parse or holds a count beyond its pool is dropped, one from an older pool completed at 0, and `parseSave` says why it refuses a file, as Super Metroid's. Every change, settings and pads included, is one undo step (200 kept); `reset` keeps the settings and forgets the pads. `games/smz3/logic.ts` reads the run: `solutionOf` compiles the pack's world once per settings and solves once per items, pads and settings (without keysanity the state holds every keycard, as upstream's logic does), and `markerState` is what a marker shows. `games/smz3/module.ts` follows other tabs through `games/syncAcrossTabs.ts`, for the stream view; its history and save file are the same `historyActions` and `createSaveFormat`.

Its autotracking lives in `games/smz3/autotrack/`, as Super Metroid's: `store.ts` (`smz3Autotrack`, a game session saved under `alltp-tracker-smz3-autotrack`), `runtime.ts` (the pack's `SMZ3_AUTOTRACK`; Race Mode on until the seed's race bit says otherwise, every reading decoded again when it changes), `reading.ts` (both games' items, the locations checked, the seed and, outside Race Mode, its requirements) and `follow.ts` (`createSmz3Follower`, per session: only while the running game is in play, it lays each reading's news through `applyGameNews`, which rebases the history as Super Metroid's does: an item's count when the game's changes, or the player's if higher; the locations the game says checked, added; the seed's logic and keysanity and, outside races, its thresholds and medallions).

## Saves

- **Persisted shape changes** bump `PERSIST_VERSION` and add a step to `migrate` in `persistence.ts`, which upgrades localStorage and imported files alike; then update `toPersisted`, `restoreProgress` / `restorePrefs` together. Never bump the version without a migration — persist would silently drop every existing save.
- `validateProgress` checks every field against the current tables. `parseSave` (import) refuses a file with any invalid field and names it; rehydration from localStorage is lenient and keeps the valid fields.
- **Shared links** (`apps/web/src/share/`, `docs/share.md`): Share encodes what Export writes into the address's fragment, `#run=` plus base64url of the deflated, minified JSON. The page's `SharedRunPrompt` (among the notices of each game's app, never in the stream view) decodes it under two bounds (64 K characters of payload, 1 MiB inflated), reads the game from the envelope with Zod, then hands the text to that game's `importRun`, which is `parseSave` (the same validation and migrations as Import) and `load`/`loadProgress` (the same single undo step). Nothing is applied before Open; a link that does not decode or validate changes nothing. Another game's run is laid in its own store, then `switchGame` loads the page again (the undo point does not survive the reload). ALttPR and SMZ3 write a packed link (format `alltp-tracker-link`, `games/<id>/share.ts` over `share/packed.ts`): `checked` as a bitset over the pack's ordered locations, ALttPR's `items` and `timeline` as varints and bits, with the sizes of those ordered tables and a digest of their contents in the link: the tables are append-only (a new item goes at the end of ALttPR's `SHARE_ITEMS`, a new location at the end of the pack's), a link made against a prefix of today's still opens, and one made against tables reordered or cut is refused ("another version of the tracker"). The game's `importRun` expands it into a plain save first; a plain link (the first version's, and Super Metroid's) opens untouched. A save format change needs no link version: the packed fields are expanded back to a save, which `migrate` already reads. A table that changes order breaks the links made before it (the digest refuses them), so never reorder one; a new packed field must be added to the codec. ALttPR's link falls back to `withoutTimeline` when the full one passes 2000 characters.
- Exports are `{ format: "alltp-tracker-save", game: "alttpr", version, progress }` (localStorage also keeps `game`); a file of another game is refused, and bare objects from earlier versions still import. Version 6 checked locations by the pack's ids: its migration expands each version 5 chest flag through the pack's `LEGACY_CHESTS` and carries a keysanity counter's items found. Version 7 takes the small-key maxima from the pack: its migration brings Eastern Palace's count, which could be 1, to 0. Versions 8 and 9 add run settings a seed sets (swordless and the crystal counts; then item placement, accessibility, item pool and functionality): their migrations give every earlier run the site's defaults the tracker assumed. Version 10 names the dungeon items as alttpr.com does (`dungeonItems`): its migration turns keysanity on into `full`, off into `standard`. Version 11 counts the castle dungeons' small keys too: its migration adds their three counts, none found. Version 12 gives a keymap saved before the Half Magic cell its Slash and Shift+Slash keys, never moving a chord already held (`migrateV11`, the step to version 12). An item id added to `items` needs no version: a save without it restores it at its fresh value, and an older version ignores it.

## History

`past` / `future` hold earlier `Progress` snapshots for undo/redo (cap 200), never persisted. Every action that changes `Progress` goes through `record(state, next)`, which pushes the current run and clears `future`; prefs bypass it. Rehydration (first load, another tab via `games/syncAcrossTabs.ts`, which every game's module starts, filtered on `localStorage` and the store's key) clears the history.

What the game says is the one exception: `applyGameNews(change)` lays autotracking's news on the run as no step, and on every snapshot of `past` and `future` too, each stamped on its timeline with the same instant, so undoing the player's change never undoes the game's. It sets nothing when `change` changes nothing, so a reading with no news writes neither the store nor localStorage. "Sync from game" (`syncWithGame`) is the player's action, one recorded step. The policy (a merge that never undoes the player's marks beyond the game, a sync that does, what Race Mode leaves alone) lives in `apps/web/src/games/alttpr/autotrack/apply.ts`.

## Subscriptions

Components subscribe with selectors — `useGameStore((state) => state.items[item])` — never bare `useGameStore()`: a component re-renders only for the slice it shows. A selector must return a stable value; for several fields use one selector per field or `useShallow`.
