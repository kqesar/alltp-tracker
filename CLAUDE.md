# CLAUDE.md

Rando Atlas (the display name; the repo, URL, storage keys, Tauri `identifier` and `productName`, and updater endpoint keep `alltp-tracker`, which saved runs, links and installed apps rest on — `docs/desktop.md`) — a React 19 + TypeScript (Vite, Zustand, Biome, Vitest) web app tracking items, chests and dungeons in ALttP Randomizer runs. Package manager is **pnpm**, pinned to one exact version by both `packageManager` and `devEngines.packageManager` in `package.json`, which a bump changes together (pnpm switches to that version itself and records its binaries' sha512 in `pnpm-lock.yaml`; CI reads it too). Node comes from `devEngines.runtime`, a range (`^22`) whose exact version and checksum the lockfile fixes: `pnpm install` fetches that Node and every `pnpm` script runs with it, whatever Node the shell has; CI sets up pnpm, that Node and the frozen install in one step (`pnpm/setup`). Build scripts are denied by default, so a dependency that needs one (esbuild) is listed under `allowBuilds` in `pnpm-workspace.yaml`.

## Layout

A pnpm workspace. Dependencies point one way: `apps/web` → packs → `packages/*`, and the packages import nothing of the app or the packs.

- `apps/web` — the tracker app (`@alltp/web`); all React, Vite and Playwright code and configs. It holds no game rule: `apps/web/src/games/alttpr/logic/` reads the run through `packs/alttpr`. Each game's modules live under `apps/web/src/games/<id>/` (ALttPR's: its board, map, logic, store, autotracking, voice); `src/` itself keeps what every game shares (the entry point, the dialogs and toolbar menu, the update notice, the setup guide's screens (its model is `packages/autotrack/src/setup.ts`), the run link in `share/`, the desktop app's page side in `desktop/`, the map legend, utils, styles).
- `apps/desktop` — `@alltp/desktop`, the desktop app (Tauri 2, Rust in `src-tauri/`): `apps/web` built in Vite's `desktop` mode in a native window, updated from GitHub Releases, with global shortcuts (Rust: `src/shortcuts/`, the command line in `src/cli.rs`; the page's side under `games/alttpr/desktop/`) and live follow on the local network (Rust: `src/follow.rs`, a token-gated WebSocket relay that also serves the app's page to a phone, over `src/relay.rs`, the server building blocks, and `src/feed.rs`, the run both servers stream; the page's side: `desktop/liveFollow.ts` and the Share dialog's switch, `follow/publish.ts`, the followed view in `follow/`) and the stream view served to OBS (Rust: `src/stream.rs`, a second server on the same blocks whose switch, port and tokens are kept in `stream.json` and which starts with the app; the page's side: `desktop/runFeed.ts`, the one publisher both servers hold, `desktop/streamTools.ts` and the Stream tools dialog, and the source's own page, `follow/StreamSourceView.tsx`) with the overlay API on the same server (Rust: `src/overlay.rs`, the `/overlay` route over a numbered feed; the page's side: `overlay/`, the protocol, the diff and the publisher, each game's race-safe whitelist in `games/<id>/overlay.ts`, and `desktop/overlayFeed.ts`; `docs/overlay-api.md` is its contract). Desktop-only code in the app sits behind `isDesktopApp` (`utils/platform.ts`), which the site's build folds away; `docs/desktop.md` is the design doc.
- `apps/web/seo/` — what search engines and link previews read: a static page per game written at build time (`/alltp-tracker/<id>/`), beside `public/sitemap.xml`, `robots.txt` and the cards of `public/social/` (regenerated by `apps/web/scripts/social-cards.mjs`); `docs/seo.md` is the design doc.
- `packages/engine` — `@alltp/engine`, the game-agnostic logic engine; its README is the design doc.
- `packages/autotrack` — `@alltp/autotrack`, the game-agnostic autotracking link: the usb2snes protocol to SNI / QUsb2Snes, RetroArch's own UDP commands for the desktop app (SNI behind them), the session and its diagnostic codes, polling, Race Mode by construction, the setup-guide model. Packs supply every address, game probe and race profile; its README is the design doc.
- `packages/archipelago` — `@alltp/archipelago`, the game-agnostic Archipelago link: a read-only Tracker session on an AP room (archipelago.js, pinned, under its own timers, backoff, keepalive and a guard that refuses every packet off a read-only whitelist), the snapshot reducer, name data, diagnostics and the setup steps. The app's `archipelago` module (`apps/web/src/games/archipelago/`, `docs/archipelago.md`) is its board: AP is its own randomizer, so the board never maps a room onto the packs; it shows what the server states (items, the slot's checks by location group), with ALttPR's art for A Link to the Past and a list for any other world. Its README is the design doc.
- `packages/archipelago` — `@alltp/archipelago`, the game-agnostic link to an Archipelago room: a read-only Tracker session (archipelago.js 2.1.0, pinned exactly, on a socket the session creates, guards and times itself), the outgoing whitelist (`guard.ts`), the snapshot reducer, name data by checksum, diagnostics and the setup guide as data. `upstream.json` pins AP 0.6.8; `test/fixtures/` are recorded against it by its `record-fixtures` script, never hand-edited; `test/real-server.spec.ts` runs only with `AP_SERVER_URL`. Its README is the design doc; no app code imports it yet.
- `packs/*` — game packs (rules as data, items, map markers). `packs/alttpr` (`@alltp/pack-alttpr`) ports ALttPR v31 from the randomizer's source: `upstream.json` pins the upstream commit and maps each upstream file to its module, `test/upstream/` holds the official tests as generated fixtures, and the weekly Logic drift workflow opens a `logic-drift` issue when upstream moves. `packs/sm` (`@alltp/pack-sm`) is Super Metroid as Map Rando seeds play it: items, objectives and the autotracking memory map, read from Map Rando's source (its README; no logic, the rooms being reconnected). `packs/smz3` (`@alltp/pack-smz3`) is SMZ3 as samus.link generates it: both games' logic ported from `tewtal/SMZ3Randomizer`'s C#, held to its logic tests as fixtures its importer writes (its README); its Hyrule markers and Zelda location flags are the alttpr pack's kept as data, that pack a dev dependency only; it carries SMZ3's autotracking pack too (one ROM, a mode per running game).
- Root — shared tooling only: Biome, TypeScript (a solution `tsconfig.json`), Vitest (`projects` + coverage over every workspace), husky, commitlint. The root `package.json` carries the product version, which release-please bumps. Commit scopes follow the workspace: `web`, `desktop`, `engine`, `autotrack`, `archipelago`, `alttpr`, `sm`, `smz3`.

Documentation: `README.md` stays short (what the tracker is, screenshots, links). What players see is described in `docs/guide.md`, developer material in the other `docs/` files, indexed by `docs/README.md`. The README's screenshots come from `apps/web/scripts/readme-screenshots.mjs`.

Area rules live in `.claude/rules/` and load when you touch their files: `store.md` (state, persistence), `data.md` (game data and logic), `components.md` (UI, styles, a11y), `tests.md`, `engine.md` (the logic engine), `pack.md` (game packs).

## Quality bar

This tracker is meant to become the reference tracker for randomizer runs, so every change is held to that standard on every axis: runtime performance (renders, CPU, memory, storage), visual design (pixel-perfect at every width), accessibility and semantic HTML, code and algorithm quality, bundle size, dependencies, tests, CI and infrastructure.

- **The docs move with the code.** A change to documented behaviour updates its doc in the same pull request. `pnpm check:docs` catches a moved or deleted path and a broken link or anchor, not a description that stopped being true: that is on whoever changes the behaviour.
- **Fix what you find.** A defect noticed while working on something else — a bug, a re-render storm, an a11y violation, a flaky or vacuous test, a broken workflow — is fixed, in its own commit, without waiting to be asked. Say what was found and fixed.
- **Some duplication is the design, so leave it alone:** the upstream ports (`packs/alttpr/src/regions/` and `worlds/` per variant, kept one to one with the randomizer's files that `upstream.json` maps), the ALttPR data the smz3 pack keeps as data (markers, Zelda flags: the alttpr pack is a dev dependency only), the per-OS Rust modules that share a signature (`shortcuts/`), and the two SM packs' bit constants (packs never import each other); any other duplication is a defect to share.
- **Verify in a real browser.** UI work is driven with Playwright (screenshots at 390 / 820 / 1440 / 1920 px, real interactions) and audited with axe-core plus a check for clickable elements a keyboard cannot reach; jsdom alone misses layout and focus bugs.
- **The design stays current.** Follow interface trends that have proven themselves (in the tools players already use and in mainstream product design), not passing fads. When part of the UI starts to look or behave dated, propose its evolution to the user before or while changing it: say what feels dated and why, show examples of the current practice it should move to (named apps or sites, screenshots, mock-ups), and keep the pixel-art identity of the game assets.
- **Dependencies are welcome when they earn their place.** Add a library when it is the better engineering choice over hand-rolled code, and state why: what it replaces, its size and maintenance, and why it beats the alternative. Remove a dependency the moment it stops earning it.
- **Game rules come from the randomizer's own source**, never from memory; record the upstream commit they were read from.
- **The architecture follows the need.** Watch whether the app's structure still fits what is being built (a single store as game packs arrive, hand-written predicates against a rules engine, one package against a monorepo, client-only state against sync). When it stops fitting, propose the change before building more on top: what no longer fits and why, the options, and each one's advantages, drawbacks and migration cost.
- **The platform is a choice, not a ceiling.** Today the tracker is front-end only, deployed as static files on GitHub Pages. The day that blocks something worth building (a relay for autotracking or multi-device sync, accounts, secrets for a racetime.gg or Archipelago integration, a server-side job), say so plainly and propose concrete options with trade-offs (serverless functions or an edge worker, a small backend, the Tauri desktop app, another host) instead of working around it. Once the platform has moved, delete this rule.

## Commands

```bash
pnpm dev                     # Start dev server (vite)
pnpm build                   # typecheck, then vite build of apps/web
pnpm typecheck               # tsc over every workspace (app, its configs and e2e, engine, packs)
pnpm lint                    # Biome check
pnpm lint:fix                # Biome check --write
pnpm check:docs              # Every Markdown link, anchor and quoted repo path resolves
pnpm test                    # Run tests once (vitest run)
pnpm test:coverage           # Run tests with coverage (enforces the floors)
pnpm test:e2e                # Playwright + axe on the production build, 4 widths (~10 s)
                             # port 4173; another worktree at once: E2E_PORT=<free port>
pnpm vitest run <file>       # One spec file; add -t "name" to filter by test name
pnpm --filter @alltp/pack-alttpr import-upstream <checkout>  # Regenerate the upstream test fixtures
pnpm --filter @alltp/pack-alttpr import-er <checkout> --rom <base.sfc>  # Re-import the entrance randomizer's tables and rules
pnpm --filter @alltp/web fetch-voice-model  # The speech model (40 MB, gitignored), before test:e2e
pnpm --filter @alltp/desktop dev    # The desktop app on the dev server (Rust ≥ 1.90, ~/.cargo/bin)
```

`tsc -b` writes its build info and the config projects' output under `node_modules/.tmp`, never next to the sources: a stray `vite.config.js` would shadow `vite.config.ts`.

The `verifier` subagent runs lint, types, tests and build and returns only the failures; use it instead of reading full command output. When running a check yourself, judge it by its exit code, never by the last line of its output: Biome prints its error count before a trailing blank line.

## Conventions

- In the app, import via the `@/` alias (`@` → `apps/web/src`). The app has no barrel/`index.ts` re-export files — import from the file path; a package exposes one `src/index.ts`.
- Biome (not ESLint/Prettier) handles lint + format and sorts imports, JSX attributes and object keys. A hook runs it on every file you edit; fix what it reports.
- Code and comments in English.
- One game at a time: `main.tsx` loads the module of the game this device tracks (`games/registry.ts`: `activeGame`, saved under `alltp-tracker-game`, A Link to the Past by default; `loadGame`), each a chunk of its own, so a player never downloads another game's board. A module (`games/<id>/module.ts`) gives its `start` (what it runs once per page: each game's cross-tab sync), its two views, its `store` (what live follow publishes and applies) and `importRun` (the game's own validation of a save, which both Import and a shared link read it through). `?game=<id>` (`takeGameFromAddress`) makes a link's game the device's, as a switch does, and leaves the address; `GamePicker` (in each game's run type dialog) switches with `switchGame`: the choice saved, the page loaded again; each game keeps its run under its own key (`alltp-tracker-state` for ALttPR, `alltp-tracker-sm` for Super Metroid, `alltp-tracker-smz3` for SMZ3, `alltp-tracker-archipelago` for an Archipelago room, whose connection settings sit apart under `alltp-tracker-archipelago-connection` and are never published; its `importRun` refuses every save and link). Four entry views, picked in `main.tsx` by the query string: the tracker (`App`), the OBS stream view (`?view=obs`, `ObsView`), which shows only the grid (with `&timer=1`, the run timer under it; with `&feed=1`, an Archipelago board's last feed lines) and takes new versions on its own, the followed view (`?view=follow&token=…`, `follow/FollowView.tsx`), a device on the network watching the desktop app's run: picked before the app's start-up (the app serves its own build, which believes it runs in the app), the game's `ObsView` with `relay="follow"` in an `inert` container under a status banner, no worker, no update notice, no visit counted, and the relayed stream view (`?view=obs&token=…`, `follow/StreamSourceView.tsx`), what the desktop app serves to an OBS Browser Source: routed the same way, in both builds, the same `useFollowedRun` as the followed view but transparent, `relay="obs"`, with no banner, retrying forever (`endOnStop: false`, 5 s cap), reloading itself when the app updated, and saying only that its address is out of date (4401). `ObsViewProps.relay` is set in both relayed views, which take no key. Only the tracker autotracks or connects to an Archipelago room: the stream view follows it through storage and never opens a session. `?bridge=<port>` points autotracking at a bridge on another port (the browser tests' fake one).
- Visits are counted by GoatCounter (`utils/analytics.ts`, started from `main.tsx` after load): cookie-less, loaded async, only on `COUNTED_HOST`, never in the desktop app, the stream view or the followed view, and not for a visitor who sends Do Not Track or Global Privacy Control (GoatCounter ignores both on its own, hence the check). The site code is the one constant `GOATCOUNTER_CODE`, the owner's free account.
- The service worker (`apps/web/sw/`, production builds only) lists every built file with its content hash, so any release updates it: there is no version to bump.

## Commits

Conventional Commits, enforced by commitlint via a husky `commit-msg` hook (`feat`/`fix`/`docs`/`style`/`refactor`/`perf`/`test`/`build`/`ci`/`chore`/`revert`); body lines ≤ 100 characters. A `pre-commit` hook runs `lint-staged` (Biome) on staged files. Do not add Co-Authored-By trailers. release-please derives the version and changelog from commit types (`release-please-config.json` lists which are shown: `feat`, `fix`, `perf`, `revert`, `docs`, `refactor`), so mark a commit breaking (`!` / `BREAKING CHANGE`) only when users must act — an automatic save migration is not breaking.
